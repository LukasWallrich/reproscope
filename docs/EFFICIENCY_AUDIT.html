reproscope pilot — efficiency audit

Five Multi100 papers, 2026-09-02 to 2026-09-03. Two independent reviews (Opus subagent, GPT-5.6 Sol via Codex) over the same call ledger; both full reports are in docs/evaluation/audits/. All pipeline processes are stopped.

Verdict. A clean single run costs USD 18–38 per paper at list price, 2–4× the top of the scope's USD 2–10 envelope. Cash spend was USD 5.08 (OpenRouter); the rest, about USD 171 list-equivalent, ran on the Claude subscription, plus unpriced Codex calls. 97% of the cost sits in 114 Opus calls (about 23 per paper) that each re-read the whole paper, every page image, or every replica's output. Nothing in the design forces this: the same pipeline fits the envelope with deterministic joins, page-local arbitration, cheaper tiers for matching-type tasks, and one strong call per stage.

What v0.1 would cost

With the fixes above: about 3 strong calls per paper (contracts + redaction, broad review, interpretation), a conditional targeted arm, and cheap or deterministic everything else. Both reviews land at USD 5.5–8 per paper at list price, inside the envelope, with these stated trade-offs: no within-family dispersion by default, weaker recall on obscure supporting table cells, referee comments limited to the focal analysis, and a smaller targeted search that reports "search exhausted under budget" rather than "not reachable".

Correctness problems the audits found

  1. Stage 2 reviewed the wrong claim on Axt and Hurst. Its focal-claim lookup matches the manifest value by string equality and falls back to the first claim. Stage 3 has a manifest override now; Stage 2 must use the same binding.
  2. A failed model call was graded as a failed replication in the match table (band "fail" instead of abstained). No live artifact is affected after the rebuild, but the path is still open.
  3. Stale artifacts get blessed: a prompt edit clears the stage marker, the stage reuses every old step output, then writes a fresh marker.
  4. A crashed targeted agent is recorded as "not reachable", the strongest verdict against a paper.
  5. Token accounting is a lower bound: retries are not ledgered, the opencode route drops cache-read tokens (10–18× understated), Codex calls carry no price.
  6. The leak scan's exemptions are load-bearing (integers ≤ 30, non-headline n, threshold p-values), and the semantic audit rated every paper "strong" for structural reasons, so it cannot discriminate.
Decisions needed.
  1. Replica lineup for the rest of the pilot. Recommended: finish the five papers with the existing replica outputs (no new agentic runs), and treat the frontier-versus-cheap comparison as done for Ohtsubo, Hertel, Hurst and Axt, where all families ran.
  2. Finish or stop. Outstanding work: Petersen matching and Stage 3, the repair pass that rechecks seven replicas marked failed, and the reports. With the fixes for items 3, 6 and 9 applied first, that costs roughly USD 1 cash and USD 10–15 list-equivalent. Without them it would repeat the cascade.
  3. Apply the efficiency fixes before or after the evaluation writeup. Recommended: fix items 1–3, 5, 6, 8, 9 and the six correctness problems now (a day of work, no model calls except tests), then finish the pilot on the reduced settings, then write up.
