# reproscope v0 pilot — build design

Single source of truth for the pilot build. Every subagent implementing a stage reads this first.
SCOPE.html holds the rationale; this file holds the mechanics.

## Layout

```
reproscope/                Python package (Python 3.14, uv-managed .venv)
  cli.py                   python -m reproscope run <paper_id> --stages 0 1 2 3 report [--force] [--force-step <step names>]
  config.py                loads models.toml: tier -> {route, model}; per-stage overrides
  llm.py                   the only place that talks to models (see Model routes)
  ledger.py                append-only runs/<paper_id>/ledger.jsonl: one row per model call
  artifacts.py             pydantic models for the artifact chain + load/save + input hashing
  paths.py                 corpus/run path helpers
  stage0/                  extract.py arbitrate.py contracts.py readiness.py redact.py leakcheck.py
  stage1/                  blind.py replicas.py rerun.py match.py audit.py targeted.py diagnose.py
  stage2/                  review.py mde.py
  stage3/                  multiverse.py
  focal.py                 bind_focal_claim: shared by Stage 1's targeted arm, Stage 2 and Stage 3
  report/                  build.py (HTML + JSON sidecar), templates/
  prompts/                 <stage>_<step>.md, versioned by file content hash (recorded in artifacts)
models.toml                model configuration (user-editable)
corpus/<paper_id>/         manifest.json (tracked) + paper.pdf, data/, code/, pages/ (gitignored)
runs/<paper_id>/           stage0/ stage1/ stage2/ stage3/ report/ ledger.jsonl (gitignored)
docs/                      this file, pilot notes, evaluation writeup
```

## Manifest (corpus/<paper_id>/manifest.json)

```json
{"paper_id": "...", "title": "...", "doi": "...", "pdf": "paper.pdf", "licence": "...",
 "data_files": ["data/x.csv"], "codebook": null, "original_code": [],
 "focal_claim": {"text": "...", "source": "multi100", "claim_id": null, "reported": {"statistic": "...", "value": ..., "df": ..., "n": ..., "page": ...}},
 "multi100": {"paper_id": "...", "n_analysts": ..., "analyst_d": {"min":..,"median":..,"max":..}},
 "environment": {"language_hint": "R", "versions_named": {}},
 "design_numbers": []}
```

`focal_claim.claim_id`, when set, overrides every deterministic and model-based match in `focal.bind_focal_claim` (shared by Stages 1's targeted arm, 2 and 3). `design_numbers` lists values the leak scan and the redaction repair must treat as design facts, never as results (see Stage 0's leak scan rule).

## Artifact chain (reproscope/artifacts.py)

All artifacts are JSON files. Every artifact carries `meta`: `{artifact, version, created, stage, inputs: {name: sha256}, prompt_versions: {name: sha256}, model_calls: [ledger ids]}`.
Every claim-level artifact carries `claim_id`. Every artifact may have `state: "complete" | "abstained"` with `abstain_reason` and `confidence: "high"|"medium"|"low"` and `open_ambiguities: [str]`.

- `ClaimRecord` (stage0/claims.json, list): claim_id, study_id, claim_type (scalar|range|table_cell|qualitative|figure), importance (headline|supporting), quantity_kind (coefficient|p_value|t|F|chi2|d|r|OR|mean|sd|n|ci_bound|other), value, precision (decimals as reported), uncertainty (se/ci if reported alongside), location {page, kind: table|figure|text, label, cell}, description (the sentence or cell header), extraction {model_a, model_b, agreed: bool, arbiter_note}.
- `EstimandContract` (stage0/contracts.json, list; one per analysis, linked from claims): analysis_id, claim_ids, study_id, sample_rule, outcome, predictors, covariates, model_type, estimator, se_type, transformations, weights, missingness, software_named, versions_named, ambiguities [ {field, options, note} ].
- `DataReadinessRecord` (stage0/readiness.json): files [{path, format, rows, cols}], unit_of_observation, keys, missing_sentinels, variable_bindings [{contract_field, candidate_columns, chosen: null, note}], scale_direction_notes, weights_columns, state (complete|abstained per analysis_id).
- `RedactedMethods` (stage0/redacted_methods.md + stage0/redaction_report.json): the replica document; report lists removed spans by kind and the deterministic scan result (must be zero hits) and the leakage-audit verdict.
- `ReplicaDecisionTrace` (stage1/replicas/<family>_<run>/trace.json): replica_id, family, model, route, filters, transformations, model_formula, missingness, weights, estimator_settings, seed, software (sessionInfo / pip freeze), fixes [{description, severity: minor|major|critical (rated by separate call)}], ran (bool), run_checks {steps_done, exit_code, outputs_present, loops, n_fixes, wall_s}, hardcoding_audit {hits: [...]}.
- `ReplicaResults` (stage1/replicas/<family>_<run>/results.json): list of {claim_id, analysis_id, value, se, ci, n, note} written by the replica agent; must be produced by code, not typed.
- `ComparableResult` (stage1/match.json): per claim_id × replica (`ComparableRow`): reported, replicated, unit_check, raw_diff, std_diff (by replica se where available), sign_match, direction_flipped (the row was graded on the sign-flipped value), band (A|B|C|fail per quantity-specific rule), sigma_rule (within|outside|na), state (complete|abstained) with abstain_reason when the link step itself failed; per claim (`MatchSummary`): n_ran (usable rows, abstained rows excluded), n_abstained, n_found, n_matched, fraction_matched, fraction_a (band-A-only fraction), dispersion {decision_agreement, numeric_cv}, state (abstained when no replica produced a usable value, or when the claim's analysis was itself abstained at intake for want of data).
- `TargetedReconstruction` (stage1/targeted.json): triggered (bool), outcome (reachable|reachable_indefensibly|not_reachable|not_triggered|abstained), added_choices [], attempts, notes, diagnosis (the agent's own conjecture section, when it wrote one).
- `Diagnosis` (stage1/diagnosis.md): unblinded conjecture, labeled as such.
- `AnalysisReview` (stage2/review.json + review.md): mode=correctness, questions {coding, interpretation}; each has an answer, summary and evidence-linked demonstrated or unresolved findings. Extended reviews remain available explicitly through `stage2.run_extended`, outside the default check.
- `SpecificationSpace` (stage3/space.json): factors [{name, source: trace|grid|default|code, levels: [{value, verdict: defensible|rejected|paper, affects: estimate|inference|reporting, rationale}]}], unimplementable [{name, reason}], incompatibilities [], grid_size, runs [{spec, estimate, se, p, converged}], reported_estimate, rank, n_specs, interpretation (separate call). `state: "abstained"` with `n_specs: 0` when no defensible level other than the paper's own can change the estimate or its significance.

## Model routes (reproscope/llm.py)

One function `call(step, prompt, *, paper_id, stage, tier=None, route=None, model=None, schema=None, images=None, system=None, cwd=None, agentic=False, timeout_s=1800, log_path=None, extra=None, max_turns=None, large_context=False, reasoning_max_tokens=None)` that dispatches on models.toml (a tier resolves to `route`/`model`; a call may instead pass `route`/`model` directly, as replica runs do):

| route | invocation | used for |
|---|---|---|
| `openrouter` | POST /chat/completions with `response_format` json_schema when schema given, `usage.include=true`, provider `{sort:"price", preferred_min_throughput:40, require_parameters:bool(schema)}`; images as base64 data URLs; a 400 on the strict schema retries once with `strict:false` | vision extraction, cheap structured steps |
| `claude_p` | `claude -p --model <m> --setting-sources project [--max-turns N] --output-format stream-json --verbose --permission-mode bypassPermissions --allowedTools Bash,Read,Write,Edit,Glob,Grep` when agentic, else `--output-format json --allowedTools Read`; `CLAUDECODE`/`CLAUDE_CODE_ENTRYPOINT` unset in env; parses the last `result` event (agentic) or the sole JSON object, `total_cost_usd`, `usage` | strong arbitration/contracts/review/diagnosis/targeted; opus and fable replicas |
| `codex` | `codex exec --skip-git-repo-check -m <m> -C <cwd> [--sandbox read-only \| --dangerously-bypass-approvals-and-sandbox] -o <last_message_file> [--output-schema <file>] -` prompt on stdin; answer from the written last-message file, falling back to the text between the last bare `codex` line and `tokens used`; tokens booked as input only, since codex reports one total | second strong family (`strong_alt`, Stage 3 screen); luna replicas |
| `opencode` | `opencode run --format json -m openrouter/<m> --dir <cwd> [--auto] "<prompt>"`; parse the NDJSON stream, join `text` parts, sum `step_finish.tokens` (input, `cache.read` and `cache.write` all counted as input) and `.cost` | cheap agentic replicas (glm, deepseek) and the Stage 3 executor |

`--setting-sources project` on every `claude_p` call means only the repo's own `.claude` settings apply, never the user's global CLAUDE.md — orchestration and advisor instructions must not steer a call, and must never reach a blind replica.

Non-agentic calls whose prompt plus system text is estimated (chars/4) above 60,000 tokens are refused before any network or subprocess work, unless the caller passes `large_context=True` (used by `stage0_contracts`, which reads the whole paper once). A structured OpenRouter call caps hidden reasoning only when the caller passes `reasoning_max_tokens`; no pipeline step does, because glm-5.3-flash answers a capped structured call with reasoning and no content.

Every attempt, not just the final one, appends a ledger row: `{id, ts, paper_id, stage, step, route, model, attempt, tokens_in, tokens_out, tokens_reasoning, cost_usd, cost_usd_equiv, cost_source, duration_s, ok, error}`, plus `provider` and `finish_reason` when OpenRouter reports them. A call gets up to `MAX_ATTEMPTS` = 4 attempts. A failure is transient — retried after a pause of 20 s × attempt — when the call is not agentic, or when an agentic call died within `EARLY_FAILURE_S` = 300 s (a session that did real work before failing is not repeated blindly); a reply the host ended with `finish_reason: "error"` counts as transient, not as a schema failure. An OpenRouter retry passes the hosts that failed earlier attempts in `provider.ignore`, since price sorting would otherwise route every attempt to the same broken host. A reply that fails schema validation gets one corrected attempt with the validation error appended to the prompt. A `claude_p` reply that carries `is_error` (a 429 session limit, a 529 overload) is reported with its API status and message. `ledger.record` zeroes `cost_usd` and sets `cost_source: "subscription"` for subscription routes (`claude_p`, `codex`), and fills `cost_usd_equiv` instead: the CLI's own `total_cost_usd` when it reports one, else tokens × a per-model shadow price from `models.toml`'s `[shadow_prices]` table (USD per million tokens, for routes such as codex that report no price). `cost_usd_equiv` is used only for list-equivalent totals, never summed into cash spend; every other route gets `cost_source: "api"` and its real `cost_usd`.

Long-running agentic calls are launched with a log file per call; the driver waits on the process, never polls a timer loop.

`models.toml` names six tiers by job: `vision_a` and `vision_b` (the two independent Stage 0 extractors, and `vision_a` again for cheap arbitration crops), `cheap` (openrouter, structured steps and cheap agentic work), `mid` (claude_p/Opus, readiness; Claude Sonnet is not used anywhere), `strong` (claude_p/Opus, contracts, review, diagnosis, targeted, interpretation), `strong_alt` (codex, a second strong family for the Stage 3 screen). The replica lineup is a separate `[replicas.<family>]` table per family (`route`, `model`, `runs`): the pilot runs opus×1, fable×1 (both `claude_p`), luna×2 (`codex`), glm×2 and deepseek×2 (both `opencode`): eight replicas per paper. `[executor]` names the Stage 3 executor's route/model (`opencode`/deepseek-v4.1-flash: on Hertel's 63-specification grid it produced the same 63 estimates as glm-5.3-flash in 2 min instead of 40). `[shadow_prices]` gives a USD-per-million-token rate per model name, used only for codex's list-equivalent cost.

## Stage 0 (reproscope/stage0/)

Pages are rendered once (`pdftoppm`, DPI stepped down from 110 until every page is under 1.5 MB) and the `pdftotext -layout` text layer is extracted once; both are cached under `corpus/<paper_id>/`. Extraction (`extract.py`) runs two independent vision passes (`vision_a`, `vision_b`) over the pages in chunks of 8, concurrently, each chunk one structured call; a chunk's claim ids are renumbered and `location.page` corrected back to whole-paper numbering when the chunks are merged. Each extracted claim's page is checked against the PDF text layer (the printed value's position on the page it names): a claim whose page disagrees with where the text layer places that value is reassigned to the correct page, searched within ±3 pages of the extractor's claim. A chunk answered with an empty claim list while its pages print at least 20 decimal numbers (reference pages do not) gets one corrected call and fails the extractor if still empty; after both extractors return, one that is empty while the other is not is rerun once, and the stage refuses if it stays empty, since arbitration with one side empty would pass every claim of the other side unchecked.

Arbitration (`arbitrate.py`) merges the two extractions deterministically first: entries on the same page, of the same canonical quantity kind, with matching location labels and cells, are paired; a pair whose values agree at the coarser of the two reported precisions is an agreement and never reaches a model. What is left — one extractor's entry the other lacks, or a value conflict — goes to the cheap vision tier (`vision_a`) in batches of 20, each item shown as a rendered crop of the page region around the printed value (falling back to the whole page when the value cannot be located in the text layer, or when the crop would exceed 60% of the page height). Headline claims the cheap tier leaves unresolved get one further strong-tier call, shown the full pages; unresolved supporting claims keep the first extractor's reading at low confidence.

One strong-tier call (`contracts.py`, `large_context=True`) reads the full paper text once and emits both the estimand contracts and the redacted methods document together, so the paper is read only once. Fields that could let a contract writer copy a result across (`value`, `precision`, `uncertainty`, `comparator`) are stripped from the claims the call is shown. A leak the deterministic scan then finds in the contracts or the redacted methods is repaired locally: the offending sentence (Markdown) or JSON string leaf is sent to a cheap-tier call for a rewrite, up to two rounds, without ever re-sending the paper text. Claim descriptions and free-text contract fields are separately rewritten by a cheap-tier scrub (chunks of 40 fragments — a host cut 120-fragment replies at its 300 s limit — concurrent, cached against the source text) that removes results, directions, and significance language while keeping design facts and the choice made when the paper justified it by a result. A scan hit found in a JSON leaf that is not a string (a numeric field) cannot be rewritten and is left for the caller to see as a surviving hit.

Readiness (`readiness.py`) runs on the `mid` tier (Opus) over a deterministic schema summary of every data file (per-column type, missingness, distinct-value counts and, for a small enough set of values, their counts) plus the codebook and the contracts; it does not see the paper text. Its output binds contract fields to data columns and marks each analysis `complete` or `abstained` (for want of data), one `DataReadinessRecord`. When the manifest lists data files and no analysis is `complete`, the call is repeated once on the `strong` tier, and the stage refuses if that binds nothing either: one call otherwise gates every analysis of the paper, and a single draw can match a deposited file to no study when its row count or a coding direction differs from the paper's description.

Leak scan rule (`leakcheck.py`, pure Python, no model call): a claim is forbidden material — searched for in every printed rounding down to its reported precision — when it is a headline claim, when its quantity kind is inferential (t, F, chi2, z, d, r, OR, HR, eta2, coefficient, p_value, se, ci_bound), or when it is any numeric claim of an analysis that carries one of those two — the means and counts a paper prints beside a test recover the test. `leakcheck.result_claim_ids(claims, contracts)` returns the widened set, and every caller that has the contracts (`stage0/contracts.py`, `stage0/redact.py`, `stage1/blind.assemble`) passes it. A supporting claim of an analysis reporting no result is sample description, not a result, and is skipped. A printed form must carry at least 2 significant digits from a headline claim or a p-value, and at least 3 from any other supporting claim, before it is searched — coarser roundings collide with alpha levels and design numbers. A rounding that lands exactly on .1/.05/.01/.001 is not searched (a manuscript's own significance-level language would otherwise read as a leak). A percent sign after a number exempts it for quantity kinds a paper never prints as a percentage (t, F, chi2, z, d, r, OR, HR, eta2, p_value) — a percent-suffixed number is an exclusion rate or a sample proportion, not that claim's value — except "95% CI"/"95% confidence", which stays design text regardless of kind. Values in the manifest's `design_numbers` list, plus the focal claim's reported `n` and `df`, are exempt outright as design constants the methods must state. Degrees of freedom printed with a statistic in a claim's `uncertainty` ("t(29)", "F(1, 24)", "χ2(3)") are stripped before its numbers are taken: they follow from the sample size the contract must state, and forbidding them collided with the sample rules. Stage 0 writes its done marker only when the scan is clean; a surviving hit fails the stage, and a rerun redoes the redaction rather than the whole stage.

## Blinding (physical)

Replicas run in a fresh directory `runs/<paper_id>/stage1/replicas/<replica_id>/work/` containing ONLY: `METHODS.md` (redacted), `CONTRACT.json`, `data/` (copy of the manifest's data files and codebook, never original code), `TASK.md` (the replica instructions), and an empty `out/`. `CONTRACT.json` groups quantities per analysis: one block per estimand contract under `analyses`, each block holding that contract's fields (sample rule, outcome, predictors, model type, estimator, standard-error type, transformations, weights, missingness) plus its `quantities` — every claim the paper reports from that one analysis, each with a `claim_id` and a description but no value. Analyses the readiness record could not bind to data are dropped and listed by id under `analyses_without_data`, so replicas do not spend effort rediscovering that the data are absent; quantities no contract claims sit under `unassigned`. `stage1_replica_task.md` states the rule this grouping exists for: each analysis is fitted once, and every quantity in that analysis's `quantities` list is read out of that single fit . A block of thirty table cells is one fit.

The deterministic value scan runs over the assembled METHODS.md and CONTRACT.json, and separately over prose supplied with the data. Reported values in data tables are not treated as leakage. The model audit receives the readiness-filtered METHODS, CONTRACT and TASK files; its fingerprint must match the delivered packet. Anchored numerical or directional result leaks block launch; structural cues are recorded as a limitation. Missing or obsolete audit receipts require Stage 0 redaction to run again. Agents execute outside the repository, but this is working-directory separation, not an enforced OS sandbox. Transcript path hits are observations requiring context, not leakage verdicts.

## Replica task (stage1/replicas.py)

The replica agent: reads METHODS.md and CONTRACT.json, inspects data/, writes `out/analysis.R` (or .py), runs it, and produces `out/results.json` (one entry per claim_id it could bind, keyed by claim_id so downstream linking is a lookup rather than a model call), `out/trace.json` (ReplicaDecisionTrace fields it can fill), `out/run.log`. Rules stated in TASK.md: fit each analysis once and read every one of its quantities off that fit; reproduce the paper's analysis faithfully (same sample rules, variables, model); when the methods leave a choice open, pick the most standard option, log it in trace.open_choices, and do not try alternatives; fix seeds (`set.seed(20260901)` or the Python equivalent); never type result numbers by hand; abstain per claim with a reason when it cannot bind the claim to the data.

The agent and the re-execution check share one Python stack: a venv at `~/.cache/reproscope/replica-env` (`reproscope/replica_env.py`) holding 3.14 plus numpy, pandas, scipy, statsmodels, pyreadstat and openpyxl at the versions the repository pins, rebuilt only when those pins move. It is first on the agent's PATH, so `python3`, `python` and `pip` resolve to it, and the check re-executes the script with the same interpreter; the agent's environment is asserted to name no path inside the repository before launch. TASK.md names the interpreters (`Rscript`, R 4.6.1; `python3`, 3.14 with that stack) and requires the agent to declare anything beyond them: `out/requirements.txt` (pip format) for Python packages, `out/r_packages.txt` (one CRAN name per line) for R packages. Before the re-execution, `replicas.prepare_env` builds what they declare — a venv at `runs/<paper_id>/stage1/replicas/<rid>/env` built from the shared interpreter and holding the base stack plus the Python declarations, and an R library at `.../rlib` set as `R_LIBS_USER` — each install capped at 600 s. Both live outside the work directory the agent saw, and are built only after the agent has exited. An install that fails or times out ends the check with `ran: false`, `state: "abstained"` and `abstain_reason: "environment: <packages> could not be installed"`, distinct from a script failure; the install log heads `check.log`. `run_checks` records `interpreter`, `installed` and `env_dir`.

After each agent exits, its script executes in a fresh directory containing supplied inputs and source files, without prior results. `ran` requires exit zero, regenerated results, agreement on statistical fields, and at least one value. The hardcoding audit determines analytical acceptance separately; anything other than a clean verdict or explicit accepted adjudication remains unresolved. An adjudication carries `decision` and `reason` inside the audit object. A failed model audit is retryable. Fix severity is recorded by a separate review call. Generation inputs and verification inputs have separate fingerprints: changing checks reuses the script, while changing the blind task or data archives and regenerates it. Stage 1 refuses downstream reconstruction if no replica produces repeatable results.

## Matching rules (stage1/match.py)

Linking a claim to a replica's evidence is a lookup, not a model call, whenever the replica keyed its own `results.json` entry by `claim_id` with a non-null value (`direct_link`); when the replica's results are keyed but carry no entry for a claim, that is a computed non-answer and needs no call either. A cheap-tier call (`stage1_link_results`) is used only when the replica's results are not keyed — reading the claim's description (never its value) against the results and trace text. A link call, or a script re-execution, that itself fails to produce anything usable makes the row `state: abstained` with a reason and excludes it from every claim's `n_ran` and its fractions. Two replica traces' analytical choices (`open_choices` and `model_formula` only — the fields where replicas actually diverge) are compared once per paper by a cheap call (`stage1_trace_choices`), separately from any one claim's grading.

Grading is deterministic. A unit check first: when the linker flags a possible rescaling (unit_note), the reported-vs-replicated grade is recomputed for ×100, ÷100 and sign-flipped candidates, and the best-banding candidate is used, with the rescaling recorded. Then by quantity_kind:
- coefficient/mean/sd/d/r/t/F/chi2 (unbounded or effect sizes; sd/n/F/chi2/p_value/se/eta2/percent skip the sign gate): sign gate first (fail on opposite signs unless |reported| is negligibly small); round replicated value to reported precision; relative diff bands A <2%, B <20%, C <40%, else fail; absolute rule |diff|<0.002 when |reported|<0.001. `t` and `d` are the sign of a two-group contrast, which is a coding choice: when their sign gate fails, the flipped value is graded with the normal bands instead and the row records `direction_flipped`, with the sign-gate fail standing when the flip does not band either. The report marks such a cell "sign flipped".
- p_value: band A when both round to the same value or both are below .001, B when they merely agree on every .05/.01/.001 threshold side and the relative diff is under 50%, fail otherwise.
- OR / HR: the coefficient bands computed on the log of each ratio; a non-positive value on either side fails outright.
- ci_bound: the same relative-diff bands as its estimate. When the estimate row of the same analysis and replica was `direction_flipped`, its interval came out mirrored about zero, so every ci_bound row of that analysis and replica is regraded on the negation of the replica's counterpart bound, and the new grade is kept only when its band is better. The counterpart is found in three tiers: the other end of the interval the flipped estimate's own link recorded; failing that, the only other ci_bound row of the analysis reporting the same sample size (which keeps two intervals of one contract on different samples apart); failing that, the row's own value negated.
- n: band A on an exact match, B within 1%, else fail.
A comparator claim ("< .001") grades band A/fail on whether the replicated value satisfies the comparator, with no relative-diff banding. When the replica reports se: sigma_rule = "within" when |reported − replicated| / se ≤ 2, else "outside".

`replica_fingerprint` is the cache key for match.json: each replica contributes the sha256 of `artifacts.content_hash(trace)` (every trace field but `meta`, so a re-save that only touches provenance does not invalidate the match) concatenated with the raw bytes of its `results.json` (so a corrected results file does invalidate it).

## Targeted arm and diagnosis (stage1/targeted.py, stage1/diagnose.py)

The targeted arm binds the focal claim through `focal.bind_focal_claim` and carries the binding in its cache key. Divergence diagnosis covers all analyses and is independent of focal selection. The arm triggers only when the match summary shows the focal claim's replicas missed: under half its usable rows in band A or B, none in band A, or a numeric coefficient of variation above 0.2 across replicas; zero usable results among requested focal attempts triggers the targeted arm; satisfactory coverage and agreement do not.

When it triggers, `targeted.assemble` builds a reduced work directory — `METHODS.md` (the paper's actual methods section, sliced from the pdftotext layer by heading, every Methods-to-Results span for multi-study papers, falling back to the redacted methods only when no heading matches), `CONTRACT.json` (the focal analysis's own contract, unblinded), `REPORTED.json` (the reported values of that analysis's claims), `FOCAL.json` (the focal binding), the closest replica's script under `data/` and its own name, and `TASK.md` — and hands it to one `strong`-tier agentic call, capped at `max_turns=40` and a 3600s timeout. The agent's job is to say whether a defensible route to the reported values exists, writing `out/outcome.json` with `outcome`: `reachable`, `reachable_indefensibly`, or `not_reachable`; an outcome file that is missing, unparseable, or outside that set — including any run where the agent itself failed — becomes `TargetedReconstruction.outcome = "abstained"`; `not_reachable` is only ever the agent's own verdict. A hardcoding audit runs afterward on the agent's own script and results, same as a replica's.

The diagnosis (`stage1/diagnosis.md` and `diagnosis.json`) covers the full deterministic divergence inventory. Source limitations receive direct evidence-based dispositions; remaining groups are diagnosed in one unblinded review call. A targeted agent's diagnosis can supply evidence but cannot replace diagnosis of other analyses. Every source occurrence and replica remains mapped to its group, and incomplete or stale coverage blocks acceptance.

## Stage 2 (reproscope/stage2/correctness.py)

The default review asks two questions: whether the available code demonstrably implements the specified calculation incorrectly, and whether a specific textual interpretation demonstrably contradicts the numerical result, units, contrast, uncertainty or explicitly stated design. The reviewer receives the paper, extracted quantity identities, contracts, every available replica script in full, verified execution summaries and the exhaustive divergence diagnoses. It reports the actual inspection scope. Replica code is distinguished from author code, and fitted parameters do not establish upstream fitting correctness.

Each answer is `clear_error_found`, `no_clear_error_found` or `unresolved`. Every finding has an exact source anchor, a demonstrated or unresolved evidence status, a checkable contradiction or missing diagnostic, consequence and next check. The implementation rejects unlocated anchors and answers inconsistent with their findings. Anchoring locates evidence; it does not establish entailment by itself. No clear error found is qualified by the inspected scope.

A general causal-language rating, broad measurement or power critique, and preferences among defensible methods are outside this default check. Debatable causal interpretations do not become errors. The optional extended review functions remain available through `stage2.run_extended`; they do not contribute findings to the default report. CLI `--force-step correctness` reruns the default review.

## Stage 3 (reproscope/stage3/multiverse.py)

Focal binding must identify one analysis. An invalid manifest override or ambiguous numerical match fails rather than choosing the first contract. The focal statistic stays on its reported scale; a t statistic is not converted to d without a verified design.

The enumerator proposes analytical factors and unimplementable choices from the contract, schema and replica traces. A separate source-paper call proposes author settings with quotations; deterministic anchoring checks that the quotations occur in the paper. Attribution still requires validation that the passage supports the setting. A numerically matching replica never supplies author-method evidence.

The independent screen must explicitly accept or reject every retained level. Structured amendments merge analytical equivalents, pin factors, rewrite implementation instructions or add levels. Unresolved mandatory amendments, missing verdicts, required factors with no valid level, and unknown incompatibilities block execution. Directly expressible `reference_settings` constrain the later analysis plan. Rejected documented author settings may be executed as reference-only specifications; they never enter the defensible curve's denominator.

The grid merges known equivalents before enumeration. `GRID_CAP=256` can pin low-priority factors to documented retained author levels; otherwise dimensions are retained and execution is sampled. `EXEC_CAP=64` bounds the accepted specifications executed, with deterministic stratification seeded from the paper ID. Reference executions are additional, separately labelled observations. The sample is descriptive; no population-weighted robustness claim is inferred. A grid with no result-moving alternative records an abstention.

The executor starts from the first accepted, focal-producing replica in stable ID order, independently of numerical proximity. It receives factor instructions, screened reference settings, explicit spec IDs, a focal contract and supplied data, with reported values withheld. It writes a reproducible script, `specs.csv`, and `analysis_plan.json`. The statistical result contract declares the estimate and SE metrics, sample size, raw and once-adjusted p-values, adjustment family, alpha .05, inference procedure, and simulation counts where relevant. Unsupported required adjustments fail the affected specification.

Verification runs in a fresh source-and-input directory using the declared environment. Prior result files are absent. Every statistical field, specification identity and supplied factor label must agree after regeneration. Obvious absolute or escaping data/result paths are refused; this does not establish a security sandbox. The independent reference adapter supports directly bound independent t, paired t and Pearson correlation analyses, with explicit sample identities. It checks estimates, n and analytic p-values against original data, then perturbs direct CSV outcome columns and repeats the check. Unsupported transformations, uncertainty estimators and inference procedures remain outside independent verification. A clean computational check cannot substitute for accepted audit findings.

Ranking and interpretation use defensible rows only. Reference author executions are displayed separately. Ranks use reported-precision ties and expose rank intervals. An all-tied curve has undefined extremeness; F and other unsigned statistics do not receive a same-sign statistic. High confidence additionally requires a determinate focal binding, resolved author settings and screen amendments, and completed reference and perturbation checks.

## Resume semantics

Stage markers record immediate input fingerprints, package implementation and analytical output fingerprints. Data and codebook bytes, readiness, methods, prompts, configuration, source scripts, dependency declarations and generated results participate in the relevant checks. PDF page rendering, text extraction and vision extraction track their actual source dependencies. Proposed-factor changes invalidate the source-evidence and screen steps; ranking is recomputed deterministically and interpretation follows the executed results.

Replica and Stage 3 executor generation have separate dependency keys from verification. Changed generation inputs archive prior work and require generation; changed scripts or checks cause reverification without another agent launch. `--force` deliberately regenerates selected stages; `--force-step` targets named steps. An unavailable audit remains unresolved and cannot become a completed analytical stage merely through cache reuse. Legacy artifacts without the new fingerprints require rebuilding or reverification.

## Divergence coverage and sensitivity reporting

Stage 1 inventories all non-top-band or ungraded inferential results, failures of printed precision even within the top tolerance band, descriptive mismatches, uncomputed quantities, and between-replica numerical differences. Valid paired-sign conventions are resolved before inventorying numerical discrepancies. Related quantities and replicas are grouped by analysis and issue type, with all source IDs and rows retained. Every group gets an evidence-linked diagnosis or an explicit unresolved explanation and next check. Source limitations and rounding-compatible inequality boundaries are separate from observed substantive mismatches. A focal-only diagnosis cannot satisfy the coverage gate.

For the registered paired multiverse, full-sample analytical results are separated using `spec.sample == "full"`; analytical-dimension activity is measured only on those rows and excludes the sample field. The report gives estimate, interval-endpoint and p-value ranges separately for every scale/location estimand, with numerical specification details. Endpoint ranges are not pooled confidence intervals, and specifications are not independent votes.

Leave-one-out rows are influence diagnostics. Each deletion is matched to exactly one full-sample baseline with the same scale, location, inference, multiplicity and interval settings. The registered diagnostic uses unadjusted centred bootstrap with percentile intervals for each estimand. The aggregate reports maximum absolute estimate change and its participant IDs, change divided by baseline SE, deletion estimate/p ranges, and sign, interval-side and p-threshold changes. It also counts estimates outside the baseline interval. Duplicate deletions, mismatched baselines and wrong sample sizes fail validation; incomplete participant coverage blocks multiverse acceptance. Deletions are not crossed with the analytical grid or counted toward its dimensions. An explicit outlier-exclusion rule would be a separate analytical choice requiring its own justification.
