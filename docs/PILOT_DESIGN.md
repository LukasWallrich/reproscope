# reproscope v0 pilot — build design

Single source of truth for the pilot build. Every subagent implementing a stage reads this first.
SCOPE.html holds the rationale; this file holds the mechanics.

## Layout

```
reproscope/                Python package (Python 3.14, uv-managed .venv)
  cli.py                   python -m reproscope run <paper_id> --stages 0 1 2 3 report [--force] [--force-step <step names>]
  config.py                loads models.toml: tier -> {route, model}; per-stage overrides
  llm.py                   the only place that talks to models (see Model routes)
  ledger.py                append-only runs/<paper_id>/ledger.jsonl: one row per model call
  artifacts.py             pydantic models for the artifact chain + load/save + input hashing
  paths.py                 corpus/run path helpers
  stage0/                  extract.py arbitrate.py contracts.py readiness.py redact.py leakcheck.py
  stage1/                  blind.py replicas.py rerun.py match.py audit.py targeted.py diagnose.py
  stage2/                  review.py mde.py
  stage3/                  multiverse.py
  focal.py                 bind_focal_claim: shared by Stage 1's targeted arm, Stage 2 and Stage 3
  report/                  build.py (HTML + JSON sidecar), templates/
  prompts/                 <stage>_<step>.md, versioned by file content hash (recorded in artifacts)
models.toml                model configuration (user-editable)
corpus/<paper_id>/         manifest.json (tracked) + paper.pdf, data/, code/, pages/ (gitignored)
runs/<paper_id>/           stage0/ stage1/ stage2/ stage3/ report/ ledger.jsonl (gitignored)
docs/                      this file, pilot notes, evaluation writeup
```

## Manifest (corpus/<paper_id>/manifest.json)

```json
{"paper_id": "...", "title": "...", "doi": "...", "pdf": "paper.pdf", "licence": "...",
 "data_files": ["data/x.csv"], "codebook": null, "original_code": [],
 "focal_claim": {"text": "...", "source": "multi100", "claim_id": null, "reported": {"statistic": "...", "value": ..., "df": ..., "n": ..., "page": ...}},
 "multi100": {"paper_id": "...", "n_analysts": ..., "analyst_d": {"min":..,"median":..,"max":..}},
 "environment": {"language_hint": "R", "versions_named": {}},
 "design_numbers": []}
```

`focal_claim.claim_id`, when set, overrides every deterministic and model-based match in `focal.bind_focal_claim` (shared by Stages 1's targeted arm, 2 and 3). `design_numbers` lists values the leak scan and the redaction repair must treat as design facts, never as results (see Stage 0's leak scan rule).

## Artifact chain (reproscope/artifacts.py)

All artifacts are JSON files. Every artifact carries `meta`: `{artifact, version, created, stage, inputs: {name: sha256}, prompt_versions: {name: sha256}, model_calls: [ledger ids]}`.
Every claim-level artifact carries `claim_id`. Every artifact may have `state: "complete" | "abstained"` with `abstain_reason` and `confidence: "high"|"medium"|"low"` and `open_ambiguities: [str]`.

- `ClaimRecord` (stage0/claims.json, list): claim_id, study_id, claim_type (scalar|range|table_cell|qualitative|figure), importance (headline|supporting), quantity_kind (coefficient|p_value|t|F|chi2|d|r|OR|mean|sd|n|ci_bound|other), value, precision (decimals as reported), uncertainty (se/ci if reported alongside), location {page, kind: table|figure|text, label, cell}, description (the sentence or cell header), extraction {model_a, model_b, agreed: bool, arbiter_note}.
- `EstimandContract` (stage0/contracts.json, list; one per analysis, linked from claims): analysis_id, claim_ids, study_id, sample_rule, outcome, predictors, covariates, model_type, estimator, se_type, transformations, weights, missingness, software_named, versions_named, ambiguities [ {field, options, note} ].
- `DataReadinessRecord` (stage0/readiness.json): files [{path, format, rows, cols}], unit_of_observation, keys, missing_sentinels, variable_bindings [{contract_field, candidate_columns, chosen: null, note}], scale_direction_notes, weights_columns, state (complete|abstained per analysis_id).
- `RedactedMethods` (stage0/redacted_methods.md + stage0/redaction_report.json): the replica document; report lists removed spans by kind and the deterministic scan result (must be zero hits) and the leakage-audit verdict.
- `ReplicaDecisionTrace` (stage1/replicas/<family>_<run>/trace.json): replica_id, family, model, route, filters, transformations, model_formula, missingness, weights, estimator_settings, seed, software (sessionInfo / pip freeze), fixes [{description, severity: minor|major|critical (rated by separate call)}], ran (bool), run_checks {steps_done, exit_code, outputs_present, loops, n_fixes, wall_s}, hardcoding_audit {hits: [...]}.
- `ReplicaResults` (stage1/replicas/<family>_<run>/results.json): list of {claim_id, analysis_id, value, se, ci, n, note} written by the replica agent; must be produced by code, not typed.
- `ComparableResult` (stage1/match.json): per claim_id × replica (`ComparableRow`): reported, replicated, unit_check, raw_diff, std_diff (by replica se where available), sign_match, band (A|B|C|fail per quantity-specific rule), sigma_rule (within|outside|na), state (complete|abstained) with abstain_reason when the link step itself failed; per claim (`MatchSummary`): n_ran (usable rows, abstained rows excluded), n_abstained, n_found, n_matched, fraction_matched, fraction_a (band-A-only fraction), dispersion {decision_agreement, numeric_cv}, state (abstained when no replica produced a usable value, or when the claim's analysis was itself abstained at intake for want of data).
- `TargetedReconstruction` (stage1/targeted.json): triggered (bool), outcome (reachable|reachable_indefensibly|not_reachable|not_triggered|abstained), added_choices [], attempts, notes, diagnosis (the agent's own conjecture section, when it wrote one).
- `Diagnosis` (stage1/diagnosis.md): unblinded conjecture, labeled as such.
- `AnalysisReview` (stage2/review.json + review.md): narrow {causal_language: CLAIMS-style rating with quotes, mde: assumptions + curve values, alignment: verdict + open choices per replica}, broad {findings: [{severity, quote, location, comment}]}.
- `SpecificationSpace` (stage3/space.json): factors [{name, source: trace|grid|default|code, levels: [{value, verdict: defensible|rejected, rationale}]}], incompatibilities [], grid_size, runs [{spec, estimate, se, p, converged}], reported_estimate, rank, n_specs, interpretation (separate call).

## Model routes (reproscope/llm.py)

One function `call(step, prompt, *, paper_id, stage, tier=None, route=None, model=None, schema=None, images=None, system=None, cwd=None, agentic=False, timeout_s=1800, log_path=None, extra=None, max_turns=None, large_context=False, reasoning_max_tokens=512)` that dispatches on models.toml (a tier resolves to `route`/`model`; a call may instead pass `route`/`model` directly, as replica runs do):

| route | invocation | used for |
|---|---|---|
| `openrouter` | POST /chat/completions with `response_format` json_schema when schema given, `usage.include=true`, provider `{sort:"price", preferred_min_throughput:40, require_parameters:bool(schema)}`; images as base64 data URLs; a 400 on the strict schema retries once with `strict:false` | vision extraction, cheap structured steps |
| `claude_p` | `claude -p --model <m> --setting-sources project [--max-turns N] --output-format stream-json --verbose --permission-mode bypassPermissions --allowedTools Bash,Read,Write,Edit,Glob,Grep` when agentic, else `--output-format json --allowedTools Read`; `CLAUDECODE`/`CLAUDE_CODE_ENTRYPOINT` unset in env; parses the last `result` event (agentic) or the sole JSON object, `total_cost_usd`, `usage` | strong arbitration/contracts/review/diagnosis/targeted; opus and fable replicas |
| `codex` | `codex exec --skip-git-repo-check -m <m> -C <cwd> [--sandbox read-only \| --dangerously-bypass-approvals-and-sandbox] -o <last_message_file> [--output-schema <file>] -` prompt on stdin; answer from the written last-message file, falling back to the text between the last bare `codex` line and `tokens used`; tokens booked as input only, since codex reports one total | second strong family (`strong_alt`, Stage 3 screen); luna replicas |
| `opencode` | `opencode run --format json -m openrouter/<m> --dir <cwd> [--auto] "<prompt>"`; parse the NDJSON stream, join `text` parts, sum `step_finish.tokens` (input, `cache.read` and `cache.write` all counted as input) and `.cost` | cheap agentic replicas (glm, deepseek) and the Stage 3 executor |

`--setting-sources project` on every `claude_p` call means only the repo's own `.claude` settings apply, never the user's global CLAUDE.md — orchestration and advisor instructions must not steer a call, and must never reach a blind replica.

Non-agentic calls whose prompt plus system text is estimated (chars/4) above 60,000 tokens are refused before any network or subprocess work, unless the caller passes `large_context=True` (used by `stage0_contracts`, which reads the whole paper once). Structured OpenRouter calls (those passing `schema`) cap hidden reasoning at `reasoning_max_tokens` (default 512, overridable per call, e.g. 256 for the leak-repair and scrub calls) so a cheap reasoning model spends its output budget on the answer, not on thinking about a small JSON object.

Every attempt, not just the final one, appends a ledger row: `{id, ts, paper_id, stage, step, route, model, attempt, tokens_in, tokens_out, tokens_reasoning, cost_usd, cost_usd_equiv, cost_source, duration_s, ok, error}`. A structured call whose reply fails schema validation retries once with the validation error appended to the prompt; a CLI-route (non-openrouter, non-agentic) failure retries once after a 20s pause on the assumption it is transient (rate limits, concurrent sessions). `ledger.record` zeroes `cost_usd` and sets `cost_source: "subscription"` for subscription routes (`claude_p`, `codex`), and fills `cost_usd_equiv` instead: the CLI's own `total_cost_usd` when it reports one, else tokens × a per-model shadow price from `models.toml`'s `[shadow_prices]` table (USD per million tokens, for routes such as codex that report no price). `cost_usd_equiv` is used only for list-equivalent totals, never summed into cash spend; every other route gets `cost_source: "api"` and its real `cost_usd`.

Long-running agentic calls are launched with a log file per call; the driver waits on the process, never polls a timer loop.

`models.toml` names six tiers by job: `vision_a` and `vision_b` (the two independent Stage 0 extractors, and `vision_a` again for cheap arbitration crops), `cheap` (openrouter, structured steps and cheap agentic work), `mid` (claude_p/Sonnet, readiness), `strong` (claude_p/Opus, contracts, review, diagnosis, targeted, interpretation), `strong_alt` (codex, a second strong family for the Stage 3 screen). The replica lineup is a separate `[replicas.<family>]` table per family (`route`, `model`, `runs`): the pilot runs opus×1, fable×1 (both `claude_p`), luna×2 (`codex`), glm×2 and deepseek×2 (both `opencode`): eight replicas per paper. `[executor]` names the Stage 3 executor's route/model. `[shadow_prices]` gives a USD-per-million-token rate per model name, used only for codex's list-equivalent cost.

## Stage 0 (reproscope/stage0/)

Pages are rendered once (`pdftoppm`, DPI stepped down from 110 until every page is under 1.5 MB) and the `pdftotext -layout` text layer is extracted once; both are cached under `corpus/<paper_id>/`. Extraction (`extract.py`) runs two independent vision passes (`vision_a`, `vision_b`) over the pages in chunks of 8, concurrently, each chunk one structured call; a chunk's claim ids are renumbered and `location.page` corrected back to whole-paper numbering when the chunks are merged. Each extracted claim's page is checked against the PDF text layer (the printed value's position on the page it names): a claim whose page disagrees with where the text layer places that value is reassigned to the correct page, searched within ±3 pages of the extractor's claim.

Arbitration (`arbitrate.py`) merges the two extractions deterministically first: entries on the same page, of the same canonical quantity kind, with matching location labels and cells, are paired; a pair whose values agree at the coarser of the two reported precisions is an agreement and never reaches a model. What is left — one extractor's entry the other lacks, or a value conflict — goes to the cheap vision tier (`vision_a`) in batches of 20, each item shown as a rendered crop of the page region around the printed value (falling back to the whole page when the value cannot be located in the text layer, or when the crop would exceed 60% of the page height). Headline claims the cheap tier leaves unresolved get one further strong-tier call, shown the full pages; unresolved supporting claims keep the first extractor's reading at low confidence.

One strong-tier call (`contracts.py`, `large_context=True`) reads the full paper text once and emits both the estimand contracts and the redacted methods document together, so the paper is read only once. Fields that could let a contract writer copy a result across (`value`, `precision`, `uncertainty`, `comparator`) are stripped from the claims the call is shown. A leak the deterministic scan then finds in the contracts or the redacted methods is repaired locally: the offending sentence (Markdown) or JSON string leaf is sent to a cheap-tier call for a rewrite, up to two rounds, without ever re-sending the paper text. Claim descriptions and free-text contract fields are separately rewritten by a cheap-tier scrub (chunks of 120 fragments, concurrent, cached against the source text) that removes results, directions, and significance language while keeping design facts and the choice made when the paper justified it by a result. A scan hit found in a JSON leaf that is not a string (a numeric field) cannot be rewritten and is left for the caller to see as a surviving hit.

Readiness (`readiness.py`) runs on the `mid` tier (Sonnet) over a deterministic schema summary of every data file (per-column type, missingness, distinct-value counts and, for a small enough set of values, their counts) plus the codebook and the contracts; it does not see the paper text. Its output binds contract fields to data columns and marks each analysis `complete` or `abstained` (for want of data), one `DataReadinessRecord`.

Leak scan rule (`leakcheck.py`, pure Python, no model call): a claim is forbidden material — searched for in every printed rounding down to its reported precision — when it is a headline claim, or when its quantity kind is inferential (t, F, chi2, z, d, r, OR, HR, eta2, coefficient, p_value, se, ci_bound); a supporting claim of any other kind is sample description, not a result, and is skipped. A printed form must carry at least 2 significant digits from a headline claim or a p-value, and at least 3 from any other supporting claim, before it is searched — coarser roundings collide with alpha levels and design numbers. A rounding that lands exactly on .1/.05/.01/.001 is not searched (a manuscript's own significance-level language would otherwise read as a leak). A percent sign after a number exempts it for quantity kinds a paper never prints as a percentage (t, F, chi2, z, d, r, OR, HR, eta2, p_value) — a percent-suffixed number is an exclusion rate or a sample proportion, not that claim's value — except "95% CI"/"95% confidence", which stays design text regardless of kind. Values in the manifest's `design_numbers` list, plus the focal claim's reported `n` and `df`, are exempt outright as design constants the methods must state.

## Blinding (physical)

Replicas run in a fresh directory `runs/<paper_id>/stage1/replicas/<replica_id>/work/` containing ONLY: `METHODS.md` (redacted), `CONTRACT.json`, `data/` (copy of the manifest's data files and codebook, never original code), `TASK.md` (the replica instructions), and an empty `out/`. `CONTRACT.json` groups quantities per analysis: one block per estimand contract under `analyses`, each block holding that contract's fields (sample rule, outcome, predictors, model type, estimator, standard-error type, transformations, weights, missingness) plus its `quantities` — every claim the paper reports from that one analysis, each with a `claim_id` and a description but no value. Analyses the readiness record could not bind to data are dropped and listed by id under `analyses_without_data`, so replicas do not spend effort rediscovering that the data are absent; quantities no contract claims sit under `unassigned`. `stage1_replica_task.md` states the rule this grouping exists for: each analysis is fitted once, and every quantity in that analysis's `quantities` list is read out of that single fit . A block of thirty table cells is one fit.

The deterministic value scan (`stage0/leakcheck.py`'s `scan()`) runs over `METHODS.md` and `CONTRACT.json` in the assembled work directory before launch; any hit deletes the work directory and blocks the launch. Prose files shipped with the data (`.txt`, `.md`, `.rtf`, `.do`, `.log` — author notes, READMEs) are scanned separately once copied in; data tables themselves are not scanned, since a reported value also occurring as a data cell is not leakage. The agent then runs in a copy of the work directory outside the repository (`/private/tmp/reproscope_blind/<paper_id>/<replica_id>`), so a relative path from inside it cannot reach the paper or the extracted claims; its outputs are copied back afterwards. The LLM leakage audit (a model that has not seen the paper is shown the redacted methods and the blind contract and asked what it can infer) runs once per paper, only when the deterministic scan is clean, and is recorded but not load-bearing.

## Replica task (stage1/replicas.py)

The replica agent: reads METHODS.md and CONTRACT.json, inspects data/, writes `out/analysis.R` (or .py), runs it, and produces `out/results.json` (one entry per claim_id it could bind, keyed by claim_id so downstream linking is a lookup rather than a model call), `out/trace.json` (ReplicaDecisionTrace fields it can fill), `out/run.log`. Rules stated in TASK.md: fit each analysis once and read every one of its quantities off that fit; reproduce the paper's analysis faithfully (same sample rules, variables, model); when the methods leave a choice open, pick the most standard option, log it in trace.open_choices, and do not try alternatives; fix seeds (`set.seed(20260901)` or the Python equivalent); never type result numbers by hand; abstain per claim with a reason when it cannot bind the claim to the data.

After the agent exits, three checks run that the agent has no say in. The script is re-executed from the top in a fresh copy of the isolation directory, and `ran` is true only when it exits 0, regenerates `results.json`, and that file carries at least one value — a trace an agent produced but whose script does not independently reproduce is `state: abstained`. The script and its results are audited for hard-coded numbers (a separate cheap call). The agent's own list of fixes is rated for severity by a separate cheap call reading the fix list and the estimand contracts.

## Matching rules (stage1/match.py)

Linking a claim to a replica's evidence is a lookup, not a model call, whenever the replica keyed its own `results.json` entry by `claim_id` with a non-null value (`direct_link`); when the replica's results are keyed but carry no entry for a claim, that is a computed non-answer and needs no call either. A cheap-tier call (`stage1_link_results`) is used only when the replica's results are not keyed — reading the claim's description (never its value) against the results and trace text. A link call, or a script re-execution, that itself fails to produce anything usable makes the row `state: abstained` with a reason and excludes it from every claim's `n_ran` and its fractions. Two replica traces' analytical choices (`open_choices` and `model_formula` only — the fields where replicas actually diverge) are compared once per paper by a cheap call (`stage1_trace_choices`), separately from any one claim's grading.

Grading is deterministic. A unit check first: when the linker flags a possible rescaling (unit_note), the reported-vs-replicated grade is recomputed for ×100, ÷100 and sign-flipped candidates, and the best-banding candidate is used, with the rescaling recorded. Then by quantity_kind:
- coefficient/mean/sd/d/r/t/F/chi2 (unbounded or effect sizes; sd/n/F/chi2/p_value/se/eta2/percent skip the sign gate): sign gate first (fail on opposite signs unless |reported| is negligibly small); round replicated value to reported precision; relative diff bands A <2%, B <20%, C <40%, else fail; absolute rule |diff|<0.002 when |reported|<0.001. `t` and `d` are the sign of a two-group contrast, which is a coding choice: when their sign gate fails, the flipped value is graded with the normal bands instead and the row records `direction_flipped`, with the sign-gate fail standing when the flip does not band either. The report marks such a cell "sign flipped".
- p_value: band A when both round to the same value or both are below .001, B when they merely agree on every .05/.01/.001 threshold side and the relative diff is under 50%, fail otherwise.
- OR / HR: the coefficient bands computed on the log of each ratio; a non-positive value on either side fails outright.
- ci_bound: the same relative-diff bands as its estimate. When the estimate row of the same analysis and replica was `direction_flipped`, its interval came out mirrored about zero, so every ci_bound row of that analysis and replica is regraded on the negation of the replica's counterpart bound, and the new grade is kept only when its band is better. The counterpart is found in three tiers: the other end of the interval the flipped estimate's own link recorded; failing that, the only other ci_bound row of the analysis reporting the same sample size (which keeps two intervals of one contract on different samples apart); failing that, the row's own value negated.
- n: band A on an exact match, B within 1%, else fail.
A comparator claim ("< .001") grades band A/fail on whether the replicated value satisfies the comparator, with no relative-diff banding. When the replica reports se: sigma_rule = "within" when |reported − replicated| / se ≤ 2, else "outside".

`replica_fingerprint` is the cache key for match.json: each replica contributes the sha256 of `artifacts.content_hash(trace)` (every trace field but `meta`, so a re-save that only touches provenance does not invalidate the match) concatenated with the raw bytes of its `results.json` (so a corrected results file does invalidate it).

## Targeted arm and diagnosis (stage1/targeted.py, stage1/diagnose.py)

The focal claim is bound the same way everywhere in Stage 1 as in Stages 2 and 3: `focal.bind_focal_claim` with `allow_llm=False`, so the targeted arm and the diagnosis never pay for a guess Stage 3 has already made deterministically or by its own cheap call. The arm triggers only when the match summary shows the focal claim's replicas missed: under half its usable rows in band A or B, none in band A, or a numeric coefficient of variation above 0.2 across replicas; it does not trigger, and makes no model call, when no replica produced a usable row for the focal claim at all (nothing to reconstruct toward) or when the replicas cleared that bar.

When it triggers, `targeted.assemble` builds a reduced work directory — `METHODS.md` (the paper's actual methods section, sliced from the pdftotext layer by heading, every Methods-to-Results span for multi-study papers, falling back to the redacted methods only when no heading matches), `CONTRACT.json` (the focal analysis's own contract, unblinded), `REPORTED.json` (the reported values of that analysis's claims), `FOCAL.json` (the focal binding), the closest replica's script under `data/` and its own name, and `TASK.md` — and hands it to one `strong`-tier agentic call, capped at `max_turns=40` and a 3600s timeout. The agent's job is to say whether a defensible route to the reported values exists, writing `out/outcome.json` with `outcome`: `reachable`, `reachable_indefensibly`, or `not_reachable`; an outcome file that is missing, unparseable, or outside that set — including any run where the agent itself failed — becomes `TargetedReconstruction.outcome = "abstained"`; `not_reachable` is only ever the agent's own verdict. A hardcoding audit runs afterward on the agent's own script and results, same as a replica's.

The diagnosis (`stage1/diagnosis.md`) costs nothing extra when the targeted arm ran: its final answer may end with a `## Diagnosis` section, written with the reported values in hand, and that section is used verbatim, labelled as the targeted agent's own unblinded conjecture. Otherwise one `strong`-tier call reads the focal contract, the focal analysis's match summaries, and the two replica traces closest to the reported focal value (by `|std_diff|` where an se is available, else relative difference); its output is likewise labelled a conjecture that grades nothing.

## Stage 2 (reproscope/stage2/review.py)

Every check is scoped to the focal analysis, bound once per run in `gather()` through `focal.bind_focal_claim` (the binding Stages 1's targeted arm and Stage 3 also use); a check whose focal binding fails abstains without a model call. No check reads the whole paper: `causal_language` gets the abstract, the paragraphs carrying the focal claim's value or description (with one neighbouring paragraph either side), and the focal contract, on the `cheap` tier. `alignment` gets the focal claim, its contract, the readiness record, and every replica's traced open choices, also on the `cheap` tier. `mde` is a deterministic R computation (`power.t.test` / `pwr::pwr.r.test`) from the focal analysis's n (preferring what the replicas actually analysed) and a design classified from the contract's model_type and formula (two-group, paired, or correlation); a design or an n the classifier does not cover makes the check abstain rather than guess. `broad` is the one `strong`-tier call, reading the focal analysis's methods and results/discussion passages, the data schema (summarised to one line per column, not the raw per-value profile), the focal estimand contract, one canonical replica script in full (the replica whose focal estimate lands closest to the reported value, ties broken by replica id) plus unified diffs of every other replica's script against it (capped at 150 diff lines each), and the focal claim's match summary. Every `broad` finding's quoted anchor is checked verbatim (case- and whitespace-normalised) against paper.txt, schema.json and every replica script; findings are kept either way, with unverified ones listed separately in review.md.

## Stage 3 (reproscope/stage3/multiverse.py)

On the focal claim only, bound through the same `focal.bind_focal_claim` as Stage 2 (here with `allow_llm=True`, so a cheap-tier call breaks the tie when the deterministic passes find nothing). Seven steps, each writing its own file and skipped when that file exists and `force` is off, except the grid build, which is a pure function of the enumerator and screen outputs and is always rebuilt: 1) focal binding; 2) enumerator (`cheap` tier) proposes factors from contract, schema and replica trace disagreements; 2b) a deterministic-first, cheap-call-backed read of what level of each proposed factor the paper itself used; 3) screen (`strong_alt` tier — a different model family from the enumerator and from Stage 0/1/2's `strong` tier) labels every level defensible or rejected with a rationale and flags incompatible level combinations, then a deterministic grid build applies the screen, prunes incompatible combinations, and caps the full factorial at `GRID_CAP` = 256 (pinning or dropping low-priority factors above that); 4) an agentic executor (the `executor` route/model in models.toml, currently `opencode`/glm) takes the closest replica's script and writes one script that loops the grid and writes `out/specs.csv`, followed by deterministic verification and a hardcoding audit; 5) rank — where the paper's reported estimate sits among the converged estimates, compared at the paper's own reported precision so a value that rounds to the same figure counts as tied, not above or below; 6) interpretation — one neutral `strong`-tier prompt reading `specs.csv`, the grid's factor names and levels, whether the executed set is a sample, and the paper's reported estimate, never the paper, the contract or the ranking statistics (rank, shares and extremeness stay in `rank.json` and the report); 7) assembly into `SpecificationSpace`.

`EXEC_CAP` = 64 bounds what is actually executed: a pruned grid at or under that size runs in full; above it, `sample_specs` takes a deterministic stratified fraction seeded from the paper id — the paper's own specification first (when identifiable), then at least one specification per factor level as far as the cap allows, then a random fill of the remainder. `grid.json` records `sampled`, `sample_fraction` and `n_specs` regardless, so a reader can tell a full grid from a sample of one. `SpecificationSpace.confidence` is `"high"` unless the executor reported a verification problem or the focal-claim binding rested on a fallback rule rather than the manifest's `claim_id` override or an exact numeric match, in which case it is `"medium"`.

## Resume semantics

Each stage writes its outputs and a `done.json` with the input hashes it used; `run` skips a stage whose done.json matches the current inputs unless `--force`. Within a stage, most individual steps carry the same check one level down: a step's cached output is reused only when its recorded `meta.inputs` (or, for stage3's whole-stage marker, `_stage_inputs`) still matches and its recorded `meta.prompt_versions` still match every prompt file's current content hash (`artifacts.prompt_stale`) — an edited prompt or a changed upstream artifact is therefore never masked by a stale done.json or a stale per-step cache. Input hashes for an artifact produced by an earlier step (claims, contracts, readiness, match, replica traces) are taken from `artifacts.content_hash`, the sha256 of the artifact's fields excluding `meta`, so re-saving an artifact with an unchanged analytical payload (a provenance-only rewrite) does not by itself invalidate a downstream cache; a plain file (the manifest, schema.json, models.toml) is hashed as bytes. `--force` reruns every stage passed to `--stages` from scratch. `--force-step <step names>` reruns only the named steps (and whatever downstream steps read their output) while leaving every other step's cache in place, for the case where only one part of a stage needs redoing. Replica runs are individually resumable (a replica with both `results.json` and `trace.json` is not rerun).
