# Task: run the specification grid

Directory contents: `BASE_ANALYSIS.R` (or .py; a working script that reproduces the focal analysis), `GRID.json`, `CONTRACT.json` (the focal analysis), `data/`.

`GRID.json` holds:

- `factors`: each factor's name and its levels, every level with a `value` and a `how` instruction saying how to implement it.
- `specs`: the complete list of specifications to run, already pruned of incompatible combinations. Each entry is `{"spec_id": "spec_001", "levels": {"<factor name>": "<level value>", ...}}`.

Write `out/multiverse.R` (or .py) that iterates over `specs` exactly as given and, for each one, runs the focal analysis with every factor set to the level named in `levels`, implemented per that level's `how` instruction. Record the effect estimate on GRID.json.effect_metric (the reported test statistic in CONTRACT.json may have different units), its standard error, p-value, n, and a `converged` flag.

Read the spec list from `GRID.json` at run time. Do not build your own factorial, do not add, drop, reorder or merge specifications, and do not invent, rename or renumber spec ids.

Write `out/specs.csv`, one row per spec, including failures. Required columns: `spec_id, estimate, effect_metric, se, se_metric, p, p_raw, p_adjustment, p_family, p_index, p_threshold, inference_method, n, converged, error`. The effect_metric must equal the per-specification reporting contract (or the primary grid metric when no per-specification contract exists). SE, when available, must be for that estimate on the same metric; otherwise leave SE and se_metric empty (never attach a raw-score SE to a standardised effect). `p_raw` is the unadjusted focal p; `p` is its once-adjusted value. `p_adjustment` is none, bonferroni, holm, or fixed_threshold. For a computed family, p_family is a CSV-escaped JSON array of all independently source-bound raw p-values, and p_index is the zero-based focal index. For a fixed source per-test criterion, use fixed_threshold with per_test_alpha, p_family=[], and p=min(1,p_raw*.05/per_test_alpha); do not infer an undocumented family size or fabricate nonfocal p-values. Use p_threshold=.05 for the adjusted p; never reduce alpha as well. For no adjustment p=p_raw and p_family/p_index can be empty. If a required adjustment is unsupported, mark the affected rows failed with a reason.

Use inference_method=analytic, exact, or monte_carlo. Monte Carlo inference additionally requires integer exceedances and draws columns; compute p_raw=(exceedances+1)/(draws+1), never zero. Each factor column must state the implemented setting and agree with the grid. A failed row has converged=FALSE, empty numeric results, and an error reason. The script must regenerate outputs in a fresh copy of this directory with no previous output files, using relative paths. Do not read cached results, source files to recover numbers, or files outside this directory. Store any helper code in out/ as .py or .R files. The verifier compares every output field and independently checks sample, metric, and inference contracts.

Implement each level through the documented interface of the packages you use; do not read or deparse package source. A level you cannot implement as its `how` says after two attempts marks its specifications `converged = FALSE` with the reason in `error`, and the loop moves on: a complete `specs.csv` with some failed rows is the deliverable, a perfect script that never runs is not.

Run it, keep `out/run.log`, and write `out/notes.md` with what you had to decide to implement any level. Never hard-code estimates or realised sample counts. Use the screened seeds and the accompanying computational verification protocol’s random generator and draw-order conventions.


Also regenerate out/analysis_plan.json with {"specs": [{"spec_id": "...", "implemented_levels": {exact factor: exact implemented level, ...}, "status": "supported"|"unsupported", "reason": null or "specific unsupported operation", "family": "independent_t"|"paired_t"|"correlation", "file": "data/filename.csv", "table": null or sheet name, "header": 0, "x": "exact outcome column", "y": "exact paired/correlation second column or null", "group_column": "exact group column or null", "group_values": [first-group-code, second-group-code] or [], "id_column": "exact ID column or null", "included_ids": null or [every included ID], "equal_var": true|false, "alternative": "two-sided"|"greater"|"less"}]}.

The independent checker receives a separately translated source recipe, not your plan as its authority. It reads the data itself and checks every estimate, sample identity, emitted SE, interval, raw p-value and correction. The plan records what your implementation actually did. All spec IDs, including failed specs, need implemented_levels. Unsupported numerical verification blocks acceptance; do not declare a supported method unavailable based on legacy adapter descriptions, and never substitute a different estimator to fit a checker. Both implementations run again on a private whole-record resample. Never read or generate a plan from prior results.

For paired contrasts the declared order is x minus y; independent contrasts use group_values[0] minus group_values[1]. Choose and label that order consistently with the focal contrast and reporting contract. The estimate, signed statistic and interval must all use the declared order. If the script computes cue minus no-cue, x must be the cue column and y the no-cue column. Never change signs to match a reported target.

For independently supported paired resampling, analysis_plan must declare algorithm=sign_flip or centred_bootstrap, test_statistic=mean_difference or studentized_mean, resampling_unit=paired_difference, alternative, draws and seed. Centred bootstrap also requires null_centering=subtract_observed_mean. These must equal screened reference_settings and your actual implementation. Explicitly declare unsupported designs instead of inventing assumptions. Include the same output fields on each rerun; never populate an SE with uncertainty on a different metric.

Report fields effect_group, null_group, estimator, ci_lower, ci_upper, and ci_method for every row. Use the screened level metadata to derive groups. For comparable raw differences use one group across justified trimming/outlier alternatives; do not create a group per estimator. If a related alternative uses different units, declare its actual effect_metric and separate effect_group. Retain a named null_group for tests of materially different nulls. Inferentially equivalent choices may share a null group even when SEs or p-values differ. Blank intervals mean unavailable; do not manufacture normal intervals. Always validate pairing, sample filters, and the uncertainty method for the actual estimator. Include these fields in analysis_plan.json as well. The uncertainty method must not be an ordinary-mean t interval attached to a trimmed mean.

Declare actual transformations, outlier rules and trimming fractions in each plan. n is the retained participant count after missingness, scoring and outlier exclusions, before order-statistic trimming. included_ids lists exactly those retained participants, derived from current data; recompute selection on each rerun. Keep any eligible starting IDs in a separately named field. Older reference_settings describing starting IDs do not override this realised-sample reporting rule. The independent recipe applies source selection and transformations itself. For paired analyses transform condition values before differencing and apply outlier rules on the selected scale. Preserve the precise screened trimming method and its corresponding winsorised uncertainty.

GRID.json.reporting_contracts maps each spec_id to the independently screened effect_group, effect_metric, null_group, null_value, and role. Copy these labels exactly to output rows and compute the quantity they identify. Do not invent group labels or infer grouping from observed results. The per-spec contract takes precedence over the grid's primary metric for explicitly related-effect specifications.

Interval identity: include ci_level (e.g. 0.95) and ci_method for every nonempty interval. Analytic location intervals use ci_method="student_t" and the estimator-specific degrees of freedom; record ci_level in the plan too. Use percentile_bootstrap for participant percentile intervals, bca_bootstrap for BCa, fisher_z for a supported Fisher interval, and student_t for estimator-matched analytic location intervals. Every emitted interval must be independently verified. Never label a resampling SE as the analytic SE.

CI controls are independent of null-test controls. Combine the selected levels' ci_reference_settings into a nested ci_settings object in each analysis-plan entry, preserving all declared fields. Flat algorithm/draws/seed fields describe the null test; ci_settings describes interval construction. Run the stated CI algorithm even when the p-value uses a different algorithm. Never use a CI bootstrap distribution as an uncentred null distribution. Preserve the selected robust estimator exactly: paired marginal trimmed-means Yuen and a trimmed mean of paired differences are different operations. A missing independent method blocks acceptance; do not change or relabel the screened estimator to obtain a pass.
