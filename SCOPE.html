reproscope

An open-source tool that puts a social-science paper through escalating scrutiny: does it compute, is the analysis sound, does the result hold up across defensible alternatives. It needs only the paper and its data. Where the original analysis code is provided, the code is re-run and its results are compared with those reconstructed from the paper alone, but the question whether the paper by itself allows the results to be reproduced is always answered.

Status: experiment. This project is exploratory and open from the start. It may or may not yield a broadly useful tool, depending on initial results and my capacity. Contributions are welcome, but please check first whether they match the direction, and make sure AI-generated code is reviewed.

Design principles

  • Surface errors and ambiguities; provide context on analytical choices and robustness. Stage 1 findings usually call for action, be it a clearer methods description or a fix. Stages 2 and 3 are context that a human reviewer weighs; their accuracy is assessed in future evaluations.
  • Runs end-to-end by default and always produces a report. Uncertainty is reported prominently. Handover artifacts (the extracted claims, the estimand contracts, the multiverse specification) are editable, and the pipeline can be restarted from any of them.
  • Two modes. Batch mode runs unattended over a corpus. Interactive mode, packaged as a Claude Code skill, walks through the same pipeline and stops at each decision point with the options and a resolution instruction. Interactive mode is also the validation tool: it makes the intermediate decisions visible.
  • Balance model strength against cost. Every stage names the model tier it needs. Cheap models do implementation and enumeration; strong models do arbitration, screening, diagnosis and interpretation. Models are user-configured so that accuracy and budget trade-offs can be tested.
  • Blind where it matters. Anything that writes analysis code never sees the paper's results. Everything that judges the paper sees all of it.
  • Open, with bring-your-own key or subscription. MIT licence, public repository, and no dependency on a single provider.

What it does

Stage 0 · Intake & extraction → Stage 1 · Computation → Stage 2 · Analysis review → Stage 3 · Robustness → Report

Different stages, different interpretations. Stage 1 highlights issues that should usually be addressed, be it by specifying the methods more clearly or by fixing errors. Stages 2 and 3 are context for human evaluation and are labeled as such, with accuracy assessments pending future analyses.

The inter-stage contract

Every stage consumes and produces typed, versioned artifacts, and every downstream output retains the claim identifier it descends from. The chain:

ClaimRecord → EstimandContract → DataReadinessRecord → ReplicaDecisionTrace → ComparableResult → SpecificationSpace

Each artifact records provenance, confidence, failure state, and the exact upstream artifact it used. Every stage may return abstained instead of a result, and abstention propagates: a claim whose estimand cannot be bound to the data produces no match table, no dispersion metric, and no multiverse, but a recorded abstention with a reason. Each claim therefore ends in one of two states, complete or abstained. Abstentions caused by missing data or inputs are excluded from every summary rate, so a replica that reports "cannot be attempted" is never scored below one that guesses. A complete result carries a confidence level and the list of open ambiguities (choices the replicas had to make because the paper or the data left them open), so the report is honest about what it rests on. The report tracks abstention rate and, on ground-truth corpora, the silent-error rate.

Stage 0 — Intake, extraction & data readiness

Two vision models, cross-checked · strong-model arbiter · deterministic guards
  • Input is a per-paper manifest: PDF, data file(s), optionally a codebook and the original analysis code, optionally a focal claim. Codebooks will usually be absent, so matching variables to the paper's descriptions is part of the task; variable labels in the data or a codebook improve accuracy and are recommended. No auto-fetching in v1.
  • Extraction covers all reported results: every quantity, its report location, and the description attached to it. Stage 1 reproduces everything the data allow. Stages 2 and 3 focus on the inferential claims in the abstract, or on a user-selected claim.
  • Each claim becomes a typed ClaimRecord → EstimandContract: claim → study/sample → variables → estimand → report location (table or figure cell, or a passage in the text) → uncertainty quantity. Each record carries a claim type (scalar, range, table, qualitative, figure), which selects the comparison rule later, and an importance level (headline or supporting), which weights the summary. Analysis-level settings that apply to every coefficient from one model (model type, estimator, standard-error type, transformations) are recorded once per analysis and linked from each cell. Multi-study papers get per-study contracts. Where the paper designates a main analysis with robustness checks, the main analysis is the contract; where several approaches are presented without ranking, all are extracted and reported together under one claim.
  • Two independent vision models extract the results; a strong-model arbiter resolves disagreements field by field (report location, value, estimand). Residual disagreement is recorded as low confidence on the record. On ground-truth corpora, extraction accuracy is scored directly.
  • Open design question for the pilot build: whether the analytical-choice part of the contract (model, estimator, covariates) is extracted here, or only in Stage 1's reading of the redacted methods, which has to return to the full text anyway. Stage 0 certainly owns quantities, locations and descriptions.
  • A data-readiness check inventories files, infers and cross-checks the schema (unit of observation, keys, missing-value sentinels, scale direction, weights, derived variables), and records variable provenance. Where the data offer several plausible bindings (several versions of a covariate, an unspecified exclusion rule), the check records the options; replicas choose and log their choice, and the ambiguity is surfaced in the report and offered to Stage 3 as a multiverse dimension. The stage abstains only when the claim cannot be bound to the data at all.
  • The stage produces a results-redacted methods document. The redaction policy distinguishes numbers by kind: design numerals (years, thresholds, scale ranges, lags, sample rules) stay; outcome information goes in any form, including values, rounded variants, intervals, significance stars, signs, and result language ("negative relationship", "significant association"), also in captions and methods-interleaved passages. Directional hypotheses are removed from the replica document as well, since together with publication they hint at the result; Stage 2 reads the full paper and sees them. Enforcement is layered: an LLM redactor, a deterministic value scan over both the redacted document and the estimand contracts (which blocks the run on any hit), and a semantic leakage audit, in which an LLM judge that has not seen the paper tries to infer the results from the redacted material. The audit is mandatory during development and an optional pass at runtime.
  • The redacted document is attached to the report by default so the blinding can be audited. Sharing a report beyond self-review requires that the paper's licence permits redistribution of its text (CC-BY or similar).
Vision extraction, redaction and leak-check: adopted from Kohler et al. (three teams independently found vision beats the PDF text layer). New: the two-model cross-check with arbitration, the estimand contract, the data-readiness check, and the kind-aware redaction policy.

Stage 1 — Computation (worth acting on)

Re-run arm where code exists · blind reconstruction: k = 6 replicas, 3 model families × 2 runs, lineup settled by calibration · targeted reconstruction on mismatch
  • Re-run arm. When the original analysis code is supplied, it is executed in parallel with the reconstruction arm, in a matched environment where the paper names versions. Its output is compared with the reported values and, separately, with the reconstruction arm. Agreement between the two arms is stronger evidence for the paper's reporting than either alone; disagreement is the most informative input to the divergence diagnosis. The arm is quarantined from the replicas, which never see the original code. Environment reconstruction for arbitrary archived code is its own engineering problem and is scheduled for v2.
  • Reconstruction arm. Each replica independently re-implements the analysis from the redacted methods, the estimand contract, and the data. Replicas never see the paper's results: supplying them can trigger fabrication or overfitting (accuracy on non-reproducible tasks drops from 100% to 63% when the PDF is provided; Alizadeh et al. 2026a). A hardcoded-results audit, taken from Kohler et al., has a model scan each replica's code for numeric literals that appear as statistical results without a computation path from the data. Every fix a replica applies to make its code run is rated minor, major or critical by a separate model call, so silent changes to the analysis are visible in the trace.
  • Before any comparison, deterministic checks on each replica's run log (all planned steps executed, exit codes, declared output files present, repeated-command loops, number of fixes, wall-clock time) sort replicas into "ran" and "failed to run". Only replicas that ran enter the match table and the dispersion metric; failures are reported as their own category.
  • Each replica emits a ReplicaDecisionTrace in a fixed schema: filters, transformations, model formula, missingness handling, weights, estimator settings. Dispersion is reported on two levels, decision-vector agreement and numeric-output agreement. Decision vectors are compared by an LLM judge for equivalence, since the same choice has many names and many equivalent implementations.
  • What the dispersion metric is: replica dispersion conditional on the shared extraction and toolchain. High agreement can be shared training priors or a common mistake, low agreement can be agent randomness or extraction error, and common-mode Stage 0 errors are invisible to it. With 3×2 the within/between-family split stays descriptive; whether dispersion predicts correctness could be a fruitful research direction using this framework, with ground-truth corpora (papers whose reproducibility is known) providing the reference.
  • Families: glm-5.3-flash, gpt-5.6-luna, and deepseek-v4-flash as the initial lineup; replicas read redacted markdown, so vision capability only binds Stage 0. The calibration run starts with frontier models to establish what is achievable, then tests whether the cheap lineup reaches it.
  • Stochastic estimation. Replicas fix their seeds and match the paper's stated number of bootstrap draws or MCMC iterations. When a replica's result sits near a decision threshold, its code is re-run over several seeds (compute only, no LLM tokens) and the seed sensitivity is reported next to the result. The multiverse in Stage 3 aims to contain substantively defensible analysis choices only. Switching a stochastic step on or off also changes later random draws, so seed noise cannot be fully separated from it.
  • Execution happens in one pinned Docker image (R and Python scientific stacks). When a paper names specific versions, their replicas get a matched environment. Version-sensitive defaults (estimator, optimizer choice) are recorded in the decision trace and fed to the divergence diagnosis; they enter the multiverse only when both settings are pre-specified as defensible.
  • Matching uses quantity-specific equivalence rules, with the Kohler bands (sign gate, round to reported precision, A <2% / B <20% / C <40%, absolute threshold <0.002 when |x| < 0.001) as the base scheme for unbounded coefficients only; p-values, odds ratios, standardized effects, and bounded or transformed statistics get their own rules, and unit rescaling is checked before grading. Matching has two steps: a cheap model reads each replica's output and writes the replicated value, its uncertainty and its location into the claim's structured record, one claim at a time with no other claim in context; a deterministic rule then assigns the verdict. When a replica reports its own standard error, the verdict also uses a sigma-based rule (is the reported value within the replica's uncertainty). Tables are graded cell by cell and summarized as a fraction matched, never as pass/fail per table. The report always shows raw and standardized differences, the paper's reported precision, and uncertainty next to any band.
  • What a match means, stated in the report: a close match shows one route to the reported number exists; a mismatch does not identify whether the paper or the replicas are wrong (or underspecified). It triggers the targeted reconstruction and the diagnosis pass, and should be read jointly with the dispersion metric, the re-run arm where present, and Stage 3.
  • Targeted reconstruction arm. When the blind replicas mismatch or disperse widely, one strong-model agent that sees the reported values starts from the replicas' code and traces and searches the space of defensible choices until it reaches the reported numbers or gives up. It answers a question the blind arm cannot: is the result reachable from this data at all? Its outcome is one of three, each reported with the list of choices the agent had to add and the number of attempts it took: reachable with defensible choices (the result exists; the methods are underspecified, and the added choices are the concrete list of what the paper should have stated, and candidate multiverse dimensions); reachable only with choices the Stage 3 screen rejects (a red flag with its own label); not reachable (the strongest available evidence for an error or a data-version mismatch, short of the original code). The arm is subject to the hardcoding audit and the rated fix log, contributes nothing to the match table or the dispersion metric, and feeds only the diagnosis and the ambiguity list. On corpora where the original code exists, it is evaluated by whether the choices it finds are the ones the code made.
  • Divergence diagnosis: one unblinded strong-model pass over the paper, all replica traces and code, the targeted reconstruction, and the re-run arm where present, writing "plausible sources of divergence". Labeled conjecture, placed below the match table.
  • Reporting is broken down by analysis family (OLS/ANOVA, multilevel, SEM, meta-analysis, …) with no a-priori exclusions. The tool's reliability limits per family could be a fruitful area for evaluation.
Blinding, templates, tolerance bands, diagnosis pass: adopted from Kohler et al. New: the re-run versus reconstruction comparison, the k-replica dispersion design, the targeted reconstruction arm, decision traces, and quantity-specific matching.

Stage 2 — Analysis review (context)

Narrow focused checks plus one broad review pass · strong model · reads the full paper
  • Narrow checks, each with an external anchor: causal language versus design strength (the Haber CLAIMS rubric, validated with human-rated reference data (Haber et al. 2018)); a minimum-detectable-effect / sensitivity curve under explicit, stated assumptions (variance structure, clustering, attrition); and claim–analysis alignment, which judges whether the analysis in the estimand contract answers the claim as worded. The alignment check also lists where the contract left choices open and how each replica filled them, so the reader sees which of the replicas' choices the claim depends on.
  • Broad check: one open-ended review pass over the paper, the data schema, and the replicas' code and results, asking for coding errors, inappropriate analytical choices, and measurement-validity concerns. It is prompted like an analysis-focused referee report, with quotes anchored to the paper or the code so every comment can be checked. Full peer review of the paper is out of scope; coarse.ink (coarse) covers that, but does not touch data or code.
  • Both kinds of check run in the pilot, so their usefulness can be compared. The ERROR corpus of expert-confirmed errors in psychology papers (error.reviews; Elson 2024) is the evaluation target for the broad check.
New assembly; the narrow checks are anchored in published instruments.

Stage 3 — Robustness (context)

Cheap model enumerates · strong model screens · cheap models execute · strong model interprets
  • The specification space is the union of three sources: the replicas' organic disagreements (from their decision traces); a systematically enumerated decision grid (exclusions, operationalizations, covariates, estimators) built from the methods and data schema; and standard-practice defaults even where the paper is silent (e.g. outlier treatment). Where original code exists, its decision points are a fourth source.
  • An adversarial reasonableness screen classifies each factor level as defensible or not, logging a rationale for every rejection, so the reader can judge the space as well as the curve. A second pass flags incompatible combinations (e.g. an outlier rule that only makes sense with a parametric model), and the remaining full grid is run. This is a key, and unsolved, step in constructing an appropriate multiverse: in Miao et al. (2026) 86% of mutually contradictory analyses passed AI review and 78% passed human expert review (the paper reports no test of that difference; screening is hard for both). The screen uses a different model family than the enumerator, may propose adjustments to the grid, and is evaluated against the Multi100 analysts' choices, which serve as a human reference set of what experts considered defensible for the same papers.
  • Execution goes through an existing engine (specr, multiverse or boba, chosen in the pilot); PIMA (Girardi et al. 2024) is a candidate for valid inference over the set. Nonconvergent and failed specifications are reported as a category.
  • The extremeness measure: the rank of the paper's reported estimate within the distribution of estimates across the screened specification space, conditional on the declared enumerator and screen. The m-value framing (Miao, Pritchard & Zou 2026) and its p-value analogy are a candidate headline once the enumerator and screen have been evaluated.
  • Estimation and interpretation run as separate, differently prompted stages, and the interpretation is itself LLM-written. On the Breznau et al. (2022) many-analysts data, Alizadeh et al. (2026b) found that a confirmatory prompt flipped Claude Code's verdicts from 10% to 90% "supported" while the coefficient distributions stayed unchanged; the bias sat in the interpretation step. Separating it lets the interpretation be prompted neutrally and checked against the curve.
The core novel stage. Kohler et al. name exactly this as future work.

Report

  • One HTML report per paper (results table with per-quantity match summaries, dispersion metrics, re-run versus reconstruction comparison where code exists, specification curve with the conditional extremeness rank, analysis-review commentary), plus a machine-readable JSON sidecar carrying the full artifact chain for batch aggregation.
  • Limitations and the interpretation differences between Stage 1 (worth acting on) and Stages 2–3 (worth considering) are stated at the top, along with per-claim outcome states, confidence levels and open ambiguities. The redacted methods document, estimand contracts, and all replica code and traces are attached by default for audit.
  • A deterministic-checker appendix wraps existing tools (metacheck modules, statcheck on source formats), with coverage statistics printed next to the flags.

Models & orchestration

  • Multi-model orchestration is the scale strategy. Kohler et al. suggest expensive models may be needed; the bet here is that k cheap replicas from different families plus strong-model reasoning stages can beat one expensive generalist at batch scale. Scaffolding matters at least as much as model size: with the same model held fixed, the Claude Code scaffold lifted broken-R-script repair from about 53% to 96% (Shah, Hopfgartner & Bleier 2026), and I4R's replication engine reports a quantised glm-4.7-flash matching all 16 published metrics of a test paper. Models are user-configured, so that evaluation is simple and accuracy/budget trade-offs can be considered.
  • Cheap tier (replicas, specification enumeration, output-to-claim linking): glm-5.3-flash ($0.075/$0.25 per MTok at the launch discount, roughly $0.15/$0.50 after 9 September 2026), gpt-5.6-luna ($0.20/$1.20, doubling above 272k prompt tokens), deepseek-v4-flash.
  • Strong tier (extraction arbitration, specification screening, divergence diagnosis, analysis review, multiverse interpretation): GPT-5.6 Sol via Codex CLI and/or Claude Fable or Opus via claude -p.
  • Agentic versus chat-style calls: anything that writes or runs code (replicas, re-run arm, multiverse execution) goes through headless agentic CLI clients (claude -p, codex exec, opencode run --format json -m provider/model). Extraction, redaction, enumeration, screening, diagnosis and interpretation are single structured-output API calls (OpenRouter with price sort and a throughput floor; Z.ai's Anthropic-compatible endpoint). A standalone Python driver routes both kinds. Bring-your-own key or subscription is a design requirement.
  • Cost: experiment toward the floor within a design envelope of roughly $2–10/paper. The driver records tokens and cost per run so real numbers are reportable. Seed reruns and multiverse execution cost compute, not tokens.

Relation to prior work

reproscope extends the Kohler et al. (2026, arXiv:2604.21965) re-derivation design from verdict benchmarking to robustness measurement. It replaces single-shot reproduction with a multi-model run that allows for more nuanced diagnostics, and locates the paper-stated specification within its defensible (multiverse) analysis space.

Previous work established that LLMs can re-run code, and also recreate code from methods descriptions, yet it rarely addressed whether the analyses were appropriate and robust, and rarely packaged them in easy-to-use ways. Conversely, AI reviewers like coarse.ink can offer helpful review comments, but do not touch data and code. reproscope aims to bridge these approaches.

Kohler et al. established the core re-derivation machinery on 48 pre-certified reproducible I4R papers: vision-based extraction from rendered pages, results-redacted methods documents with a numeral leak-check, blinded implementation templates, tolerance grading, and an unblinded diagnosis pass. reproscope adopts those elements with attribution. Other harnesses contribute ideas Kohler et al. did not use, and reproscope takes four of them: ReplicatorBench (Nguyen et al. 2026) makes the agent preregister its analysis plan before executing and treats code access as an experimental variable, which is where the decision trace and the two Stage 1 arms come from; PaperRepro (Zhang et al. 2026) forces reproduced results into artifact files rather than the agent's context and is the only system with a controlled ablation showing that merging stages costs 10–13 accuracy points; I4R's replication engine tracks extraction recall and precision as first-class metrics and stores a page-and-region pointer for every extracted quantity; and CORE-Bench's (Siegel et al. 2024) empirical tolerance (the 95% prediction interval of repeated runs) is more principled than any fixed band where several executions are affordable. VERITAS (Liu, Tjiaranata & Tan 2026), a replication executor with a verification wrapper, contributes the typed and importance-weighted claim schema, the split between an LLM that extracts the replicated value and a deterministic rule that grades it, cell-level partial credit, the severity-rated fix log, and the run-log checks that separate "failed to run" from "ran and disagrees". It has no multiverse, no repeat runs and no analysis review, and its own results show that blind reconstruction with a frontier model barely beats a plain agent session on the headline match rate while clearly improving trajectory honesty; see research/veritas_digest.md. Beyond all of these, reproscope adds:

  • Multiverse + extremeness measure. Kohler et al. classify robustness to alternative specifications as a reproducibility type they did not address and name it as future work. Their observation that agents succeed when "implicit assumptions happen to align with the original implementation" hints at the importance of identifying and testing these assumptions.
  • Multi-model runs with dispersion as a diagnostic metric. Kohler et al. already show that non-deterministic LLM runs lead to coefficient differences across about half of repeated runs. Here, we aim to indicate the extent of such variation and begin to surface its drivers by running reproduction multiple times across multiple models, and reporting the resulting differences in implementation and results.
  • Re-run versus reconstruction. Where original code exists, both arms run and are compared, which tests the reporting of the analysis rather than only its execution.
  • Targeted reconstruction. On a mismatch, an unblinded strong-model search for a defensible path to the reported numbers separates "underspecified" from "not reachable", and turns the added choices into a list of what the paper should have stated.
  • A user-friendly open-source review tool, not just a proof of concept. Explicit abstention, confidence levels, a report that separates what to act on from what to consider, and a batch and an interactive mode.

Versions

  • v0 pilot, a minimal version of the full pipeline: Stage 0 extraction of all results with estimand contracts and data readiness; Stage 1 with the re-run arm where code exists, blinded replicas with decision traces, and targeted reconstruction on mismatch; Stage 2's narrow and broad checks; Stage 3 on one focal claim per paper with a broadly specified grid; abstention as a normal outcome. Run on 3–5 Multi100 papers. This doubles as the model-calibration experiment, starting with frontier models.
  • v1: Stage 3 over all abstract claims, the full enumerated multiverse with the screen evaluated against Multi100 analyst choices, the deterministic-checker appendix, the interactive Claude Code skill, batch mode over the dev corpora.
  • v2: environment reconstruction for arbitrary archived code, the ERROR-corpus evaluation of Stage 2, the I4R×PS run.

Risks and limits

  • Unattended operation is the hypothesis under test. Outcome states, confidence levels and measured abstention and silent-error rates make its failures visible; the interactive mode is the fallback if they are too frequent.
  • The multiverse is built from statistical expertise and the data schema, plus the original code's decision points where code exists. Whether an LLM-enumerated space matches what expert analysts consider defensible is measured against Multi100.
  • Prior-art proximity. Stages 0–1 follow Kohler et al. and the other reproduction harnesses closely. The contributions are the multi-model extraction and replica design, the re-run versus reconstruction comparison, the multiverse with its extremeness measure, and the packaging as a review tool. Writeups must confine the claims to those.
  • Cheap-replica quality is unproven. VERITAS reaches a 0.33 match rate on ReplicationBench with Opus 4.8 in paper-only mode, so blind reconstruction is hard even for frontier models, and a non-match from a weak replica says nothing about the paper. The calibration run starts with frontier models and then tests whether cheap families reach the same results; the lineup is settled on that evidence.
  • The extremeness rank inherits its enumerator and screen. It is conditional by construction; the rejection log makes that legible.
  • Blinding is difficult and must be validated. The deterministic scan catches exact values only; the LLM-judged leakage audit is what measures the rest, so it is mandatory during development.
  • Contaminated dev corpora. All open ground-truth corpora are public; I4R×PS, with nothing released, is the only set unlikely to be memorized.
