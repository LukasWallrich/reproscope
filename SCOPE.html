reproscope

An open-source instrument that puts a social-science paper through a pipeline of escalating scrutiny: does it compute, is it sound, does it hold up. It needs only the paper and its data, not the original analysis code.

Status: experiment. This project is exploratory and open from the start. It may or may not yield a broadly useful tool. Findings about where it fails count as deliverables alongside the tool itself.

Positioning

reproscope is an open review-stage instrument that extends the Kohler et al. (2026, arXiv:2604.21965) re-derivation design from verdict benchmarking to robustness measurement. It replaces single-shot reproduction with a k-replica agreement statistic and locates the published specification within its defensible analysis space (m-value).

Kohler et al. already established the core re-derivation machinery on 48 pre-certified reproducible I4R papers: vision-based extraction from rendered pages, results-redacted methods documents with a numeral leak-check, blinded implementation templates, tolerance grading, and an unblinded diagnosis pass. reproscope adopts those elements with attribution rather than re-inventing them. It makes three contributions of its own:

  • Multiverse + m-value. Kohler et al. classify robustness to alternative specifications as a reproducibility type they did not address and name it as future work. Their observation that agents succeed when "implicit assumptions happen to align with the original implementation" describes exactly the quantity the multiverse measures.
  • k-replica agreement as a primary statistic. Their agreement analysis requires ground truth, which does not exist for an unvetted paper. Replica-to-replica agreement needs no target, and their finding that about half of coefficients differ from themselves across repeated runs is the case for k>1.
  • A review-stage instrument, not a benchmark study. Their corpus was pre-certified reproducible, so their grades never had to answer "what does a C mean for an unknown paper?". reproscope must: complete claim coverage, and a report that separates decision-relevant output from context.

Planned: contact Kohler and Ash. No repo or data-availability statement exists, their per-cause failure counts are unpublished, and this extension sits on the axis they disclaimed, so a collaboration or materials-sharing ask is natural. Independently, the ERROR project (Elson/Hussey) holds the ideal psychology corpus of expert-confirmed errors with no LLM arm. Evaluating reproscope's Stage 2 against it would itself be a contribution.

What it does

Intake & extraction → Stage 1 · Computation → Stage 2 · Correctness → Stage 3 · Robustness → Report

Framing rule, stated in every report header: Stage 1's match table is decision-relevant. Stages 2 and 3 are context for human evaluation and are labeled as such, never as verdicts.

Stage 0 — Intake & extraction

Two vision models, cross-checked · deterministic guards
  • Input is a per-paper manifest: PDF, data file(s), optional codebook, optional focal claim (default: all inferential claims in the abstract). No auto-fetching in v1.
  • Two independent vision models each extract the claims table from rendered pages. The run proceeds only on agreement; disagreements go to human review. This redundancy replaces a human gate, keeping the pipeline fully unattended in batch mode.
  • The stage produces a results-redacted methods document. A deterministic leak-check scans the redacted text for the claims-table values and blocks the run on any hit. The redacted variant ships with the report so the blinding can be audited.
  • Deterministic checkers (metacheck modules, statcheck on source formats, GRIM/SPRITE via scrutiny/rsprite2) run here. Their output lands in the report appendix, with coverage stats printed next to the flags.
Vision extraction, redaction and leak-check: adopted from Kohler et al. (three teams independently found vision beats the PDF text layer). New: the two-model cross-check.

Stage 1 — Computation (decision-relevant)

k = 6 blinded replicas: 3 cheap model families × 2 runs
  • Each replica independently re-implements the analysis from the redacted methods plus data. Replicas never see the paper's results: supplying them is the documented fabrication trigger (accuracy on non-reproducible tasks drops from 100% to 63% when the PDF is provided). A hardcoded-results audit, taken from Kohler, checks each replica's code.
  • Families: glm-5.3-flash, gpt-5.6-luna, third to be settled by the calibration run (not Haiku; deepseek-v4-flash qualifies since replicas read redacted markdown, so vision only binds Stage 0).
  • Execution happens in one pinned Docker image (R and Python scientific stacks). When a paper names specific versions, that replica gets a matched environment. Version-sensitive defaults (lme4/lavaan optimizers, seeds) become named multiverse dimensions rather than guesswork.
  • Matching follows the Kohler tolerance scheme: sign gate, round to reported precision, then bands A <2% / B <20% / C <40%, with an absolute threshold (<0.002) when |x| < 0.001.
  • Headline statistics: per-claim match band, plus within-family vs between-family replica agreement. The latter answers "is the methods section under-specified?", which no existing tool reports.
  • When original code exists, an additional reconstruct-and-re-run arm always runs and is reported, quarantined from the blind arms. The code also feeds the diagnosis pass.
  • Divergence diagnosis: one unblinded top-model pass over the paper, all replica code, and the re-execution arm, writing "plausible sources of divergence". Labeled conjecture, placed below the match table.
  • Reporting is broken down by analysis family (OLS/ANOVA, multilevel, SEM, meta-analysis, …). No a-priori exclusions: the tool's own reliability limits per family are findings.
Blinding, templates, tolerance bands, diagnosis pass: adopted from Kohler et al. New: the k-replica agreement design and its decomposition.

Stage 2 — Correctness (context)

Rubric-constrained LLM checks · no open-ended flaw-hunting
  • Three rubrics in v1, each with an external anchor: causal language vs design strength (the Haber CLAIMS rubric, validated with human-rated reference data); sensitivity/power given the achieved N (computed, not judged); and claim–analysis alignment, i.e. does the model actually test the stated hypothesis, checkable against the replicas' own modeling choices. Generalization-scope and measurement-validity rubrics are deferred.
  • Expected precision on checkable classes is 70–85%, based on scope-constrained evaluations. The widely cited ~6% figure comes from a benchmark with no social science content and an artifactual precision cap. No measured number exists for causal-overclaiming or design-judgment rubrics in any field, which is why the context label matters and why the ERROR-corpus evaluation is the route to one.
  • Guardrails: the paper's own abstract is never given as context when judging that abstract, and prompts carry explicit caution instructions, since LLM summaries otherwise amplify overclaiming by stripping hedges.
New assembly; individual rubrics anchored in published instruments.

Stage 3 — Robustness (context)

Top model enumerates & screens · cheap models execute
  • The specification space is the union of three sources: the replicas' organic disagreements; a systematically enumerated decision grid (exclusions, operationalizations, covariates, estimators) built from the methods and data schema; and standard-practice defaults even where the paper is silent (e.g. outlier treatment).
  • An adversarial reasonableness screen classifies each specification as defensible or not, logging a rationale for every rejection, so the reader can judge the space rather than just the curve. The screen must be scored, not decorative: 86% of mutually contradictory analyses passed AI review in Miao et al., and 78% passed human expert review.
  • Execution goes through existing engines (specr, multiverse, boba); PIMA is a candidate for valid inference over the set.
  • The report shows the specification curve plus the m-value: the probability that the published specification is at least as extreme within its own defensible analysis space (Miao, Pritchard & Zou 2026), estimated via their Agentic Bootstrap.
  • Estimation and interpretation run as separate, differently-prompted stages. A confirmatory prompt flips verdicts from 10% to 90% support while the coefficient distributions stay unchanged, so the bias sits in interpretation, not estimation.
The core novel stage. Kohler et al. name exactly this as future work.

Report

  • One HTML report per paper (claims table with match bands, agreement decomposition, specification curve with m-value, rubric commentary, deterministic-checker appendix), plus a machine-readable JSON sidecar for batch aggregation.
  • The decision/context separation is stated at the top. The redacted methods document and all replica code are attached for audit.

Models & orchestration

  • Multi-model orchestration is the scale strategy. Kohler et al. suggest expensive models may be needed; the bet here is that k cheap replicas from different families plus top-model reasoning stages beat one expensive generalist at batch scale. An escalation path stays open: if calibration shows cheap families underperforming, a top-model replica arm or arbiter is added.
  • Cheap tier (implementation, replicas): glm-5.3-flash ($0.075/$0.25 per MTok; calibration required, since GLM-5 was Kohler's worst configuration at 52% vs 72% cell completion, though 5.3-flash is a newer model) and gpt-5.6-luna ($0.20/$1.20; subscription coverage unconfirmed, test locally).
  • Top tier (extraction arbitration, spec enumeration and screening, matching, diagnosis): GPT-5.6 Sol (subscription-confirmed via Codex CLI) and/or Claude via claude -p.
  • Routing: a standalone Python driver calling headless CLI clients (claude -p, codex exec, opencode run --format json -m provider/model, installed and tested; note the ~17k-token system-prompt overhead per opencode call) plus direct API calls (OpenRouter with price sort and a throughput floor; Z.ai's Anthropic-compatible endpoint). Bring-your-own-subscription is a design requirement.
  • Cost: experiment toward the floor within a design envelope of roughly $20–50/paper. The driver records tokens and cost per run so real numbers are reportable.

  • Contamination probes: split the dev corpus at each model's training cutoff (the Kohler template). The dev corpora are public, so no dev result is claimed as generalization.
  • Validation sequence: develop on Multi100 ∪ ReplicatorBench, then the discriminant test on ReplicatorBench's non-replicable ground truth, then held-out on I4R×PS, then (for Stage 2) the ERROR corpus.
  • The headline comparison to aim for: agent crowd vs analyst crowd on identical papers. Multi100's 34% recovery within ±0.05 d is the human reference band; Holtdirk's LLM pipeline sits at 24%, and 40% vs 28% on the matched subset, with tolerance comparability between the two studies unverified.

Risks and limits

  • Prior-art proximity. Stages 0–1 are substantially Kohler et al.'s design. The contribution claims are confined to the three deltas above and must stay that way in any writeup.
  • Cheap-replica quality is unproven. Kohler's grid puts GLM-class models last. The first milestone is a calibration run before committing the family lineup.
  • The m-value inherits the screen's judgment. If the defensibility screen is miscalibrated, the m-value is too. The rejection log and adversarial design reduce this risk without removing it.
  • Stage 2 is unvalidated by construction in v1. It ships only because it is labeled context; the ERROR-corpus evaluation is the path to a real number.
  • Contaminated dev corpora. All open ground-truth corpora are public; only I4R×PS approximates held-out.
