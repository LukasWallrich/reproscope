🔬 reproscope

An open-source instrument that puts a social-science paper through a pipeline of escalating scrutiny — does it compute → is it sound → does it hold up — given only the paper and its data, without the original analysis code.

⚗️ Status: experiment. This project is exploratory and open from the start. It may or may not yield a broadly useful tool; findings about where it fails are treated as deliverables alongside the tool itself.

Positioning

reproscope is an open review-stage instrument that extends the Kohler et al. (2026, arXiv:2604.21965) re-derivation design from verdict benchmarking to robustness measurement — replacing single-shot reproduction with a k-replica agreement statistic and locating the published specification within its defensible analysis space (m-value).

Kohler et al. already established the core re-derivation machinery on 48 pre-certified reproducible I4R papers: vision-based extraction from rendered pages, results-redacted methods documents with a numeral leak-check, blinded implementation templates, tolerance grading, and an unblinded diagnosis pass. reproscope adopts those elements with attribution rather than re-inventing them. Its three genuine contributions:

  • Multiverse + m-value. Kohler et al. explicitly classify robustness-to-alternative-specifications as a reproducibility type they did not address and name it as future work. Their observation that agents succeed when "implicit assumptions happen to align with the original implementation" is precisely the quantity the multiverse measures.
  • k-replica agreement as a primary statistic. Their agreement analysis requires ground truth, which does not exist for an unvetted paper; replica-to-replica agreement needs no target. Their own finding that ~50% of coefficients differ from themselves across repeated runs motivates k>1.
  • Review-stage instrument, not benchmark study. Their corpus was pre-certified reproducible, so grades never had to answer "what does a C mean for an unknown paper?". reproscope must: complete claim coverage, and a report that separates decision-relevant output from context.

Planned: contact Kohler and Ash — no repo or data-availability statement exists, their per-cause failure counts are unpublished, and this extension sits on the axis they disclaimed. A collaboration or materials-sharing ask is natural. Independently, the ERROR project (Elson/Hussey) holds the ideal psychology corpus of expert-confirmed errors with no LLM arm — evaluating reproscope's Stage 2 against it would itself be a contribution.

What it does

Intake & extraction → Stage 1 · Computation → Stage 2 · Correctness → Stage 3 · Robustness → Report

Framing rule (report header, always): Stage 1's match table is decision-relevant. Stages 2 and 3 are context for human evaluation, explicitly labeled as such — never verdicts.

Stage 0 — Intake & extraction

Two vision models, cross-checked · deterministic guards
  • Input: per-paper manifest — PDF + data file(s) + optional codebook; optional focal claim (default: all inferential claims in the abstract). No auto-fetching in v1.
  • Two independent vision models each extract the claims table from rendered pages; the run proceeds only on agreement, disagreements are flagged for human review. This redundancy replaces a human gate — the pipeline is otherwise fully unattended batch.
  • A results-redacted methods document is produced, with a deterministic leak-check (claims-table values scanned for in the redacted text; run blocked on failure). The redacted variant ships with the report for auditability.
  • Deterministic checkers (metacheck modules, statcheck on source formats, GRIM/SPRITE via scrutiny/rsprite2) run here; their output lands in the report appendix with coverage stats alongside flags.
Vision extraction, redaction and leak-check: adopted from Kohler et al. (three teams converged on vision over PDF text). New: the two-model cross-check.

Stage 1 — Computation (decision-relevant)

k = 6 blinded replicas: 3 cheap model families × 2 runs
  • Each replica independently re-implements the analysis from the redacted methods + data. Replicas never see the paper's results — the documented fabrication/anchoring trigger (100%→63% accuracy drop when the PDF is supplied). A hardcoded-results audit (from Kohler) checks each replica's code.
  • Families: glm-5.3-flash, gpt-5.6-luna, third TBD after calibration (not Haiku; deepseek-v4-flash only if needed — replicas read redacted markdown, so vision binds only Stage 0).
  • Execution in one pinned Docker image (R + Python scientific stacks). Paper-specified versions trigger a matched per-paper environment; version-sensitive defaults (lme4/lavaan optimizers, seeds) are named multiverse dimensions, not archaeology.
  • Matching by the Kohler tolerance scheme: sign gate → round to reported precision → bands A <2% / B <20% / C <40% → absolute threshold (<0.002) when |x| < 0.001.
  • Headline statistics: per-claim match band + within-family vs between-family replica agreement ("is the methods section under-specified?" — a statistic no existing tool reports).
  • When original code exists: an additional reconstruct + re-run arm, always reported, quarantined from the blind arms; code also feeds the diagnosis pass.
  • Divergence diagnosis: one unblinded top-model pass over paper + all replica code (+ re-execution arm), writing "plausible sources of divergence" — labeled conjecture, placed below the match table.
  • Per-analysis-family reporting (OLS/ANOVA vs multilevel vs SEM vs meta-analysis …): no a-priori exclusions; the tool's own reliability limits per family are findings.
Blinding, templates, tolerance bands, diagnosis pass: adopted from Kohler et al. New: the k-replica agreement design and its decomposition.

Stage 2 — Correctness (context)

Rubric-constrained LLM checks · no open-ended flaw-hunting
  • Three rubrics in v1, each with an external anchor: (1) causal language vs design strength (Haber CLAIMS rubric — validated, human-rated reference data); (2) sensitivity/power given achieved N (computed, not judged); (3) claim–analysis alignment (does the model actually test the stated hypothesis — verifiable against the replicas' own modeling choices).
  • Deferred: generalization-scope and measurement-validity rubrics.
  • Expected precision on checkable classes: 70–85% (scope-constrained evidence); the widely cited ~6% figure comes from a benchmark with no social science content and an artifactual precision cap. No number exists for causal-overclaiming/design-judgment rubrics in any field — hence the context label carries real weight, and an ERROR-corpus evaluation is the path to one.
  • Guardrails: never feed the paper's own abstract as context when judging that abstract; explicit cautionary prompting (LLM summaries otherwise amplify overclaiming by stripping hedges).
New assembly; individual rubrics anchored in published instruments.

Stage 3 — Robustness (context)

Top model enumerates & screens · cheap models execute
  • Specification space = union of three sources: the replicas' organic disagreements; a systematically enumerated decision grid (exclusions, operationalizations, covariates, estimators) from methods + data schema; and standard-practice defaults even when the paper is silent (e.g. outlier treatment).
  • Adversarial reasonableness screen classifies each specification defensible/not, with a logged rationale for every rejection — the reader judges the space, not just the curve. (Motivation: 86% of mutually contradictory analyses passed AI review, 78% passed human expert review — an unscored screen adds little.)
  • Execution through existing engines (specr/multiverse/boba); PIMA considered for valid inference over the set.
  • Reported: specification curve + m-value (probability the published specification is at least as extreme within its own defensible analysis space — Miao, Pritchard & Zou 2026), estimated via their Agentic-Bootstrap approach.
  • Estimation and interpretation run as separate, differently-prompted stages: a confirmatory prompt flips verdicts 10%→90% with unchanged coefficient distributions — bias lives in interpretation, not estimation.
The core novel stage. Kohler et al. name exactly this as future work.

Report

  • One HTML report per paper (claims table with match bands → agreement decomposition → specification curve + m-value → rubric commentary → deterministic-checker appendix), plus a machine-readable JSON sidecar for batch aggregation.
  • Decision/context separation stated at the top; the redacted methods document and all replica code attached for audit.

Models & orchestration

  • Multi-model orchestration over single-expensive-model is the scale strategy. Kohler et al. suggest expensive models may be needed; the bet here is that k cheap replicas from different families + top-model reasoning stages beat one expensive generalist at batch scale. An escalation path stays open: if calibration shows cheap families underperforming, a top-model replica arm or arbiter is added.
  • Cheap tier (implementation/replicas): glm-5.3-flash ($0.075/$0.25 per MTok; calibration required — GLM-5 was Kohler's worst configuration at 52% vs 72% cell completion, though 5.3-flash is a newer model), gpt-5.6-luna ($0.20/$1.20; subscription coverage unconfirmed — test locally).
  • Top tier (extraction arbitration, spec enumeration/screening, matching, diagnosis): GPT-5.6 Sol (subscription-confirmed via Codex CLI) and/or Claude via claude -p.
  • Routing: standalone Python driver; headless CLI clients (claude -p, codex exec, opencode run --format json -m provider/model — installed, tested; note ~17k-token system-prompt overhead per opencode call) plus direct API calls (OpenRouter with price-sort + throughput floor; Z.ai's Anthropic-compatible endpoint). Bring-your-own-subscription is a design requirement.
  • Cost target: experiment toward the floor; design envelope ~$20–50/paper equivalent, with per-run token/cost capture so real numbers are reportable.

Risks & honest limits

  • Prior art proximity. Stages 0–1 are substantially Kohler et al.'s design; the contribution claims are confined to the three deltas above and must stay that way in any writeup.
  • Cheap-replica quality is unproven. Kohler's grid puts GLM-class models last. First milestone is a calibration run before committing the family lineup.
  • The m-value inherits the screen's judgment. If the defensibility screen is miscalibrated, the m-value is too; the rejection log and adversarial design mitigate but don't remove this.
  • Stage 2 is unvalidated by construction in v1. It ships only because it is labeled context; the ERROR-corpus evaluation is the path to a real number.
  • Contaminated dev corpora. All open ground-truth corpora are public; only I4R×PS approximates held-out.
